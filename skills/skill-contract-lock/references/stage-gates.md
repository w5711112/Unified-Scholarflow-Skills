# 阶段门禁

## 1. 原则

门禁只根据原始来源、当前适用性、实际证据和当前哈希机械推导状态。门禁名、计划、检查表、报告结论和测试数量都不能产生 `verified`。

每个阶段开始前重新打开有关原始章节；每个阶段结束时把专业工作结果绑定为当前证据回执。中央锁不解释专业文件格式或替代原始 Skill 的质量判断。

## 2. 六个通用门禁

- `G0 来源与范围`：已选 Skill、强制参考、当前任务根、授权路径和排除项闭合。
- `G1 语义与适用性`：重大语义口径、条件分支和必要用户裁决已经解决。
- `G2 方法与研究`：候选方法、依据、逻辑链和研究证据按原始 Skill 完成。
- `G3 求解与验证`：模型、代码、参数、结果和不确定性按原始 Skill 验证。
- `G4 产物与写作`：图表、文档、引用、公式、版式、语言和支撑材料按原始 Skill 完成。
- `G5 审计与交付`：最终文件正向审计、专业审计、渲染与卫生检查绑定当前哈希。

具体任务可以把原文要求分配到负责它的 gate，但不能用 gate 名反向创造章节、步骤或证据标准。

## 3. 工作阶段

`--phase work` 用于来源读取、台账建立、失效处理和普通过程检查。它验证合同结构、范围、来源、锚点、证据新鲜度和依赖关系，但不强迫尚未到期的 gate 提前完成。

## 4. 预产物门禁

`--phase pre_artifact` 要求 `G0` 至 `G3` 已完成。开始创建或实质修改论文、图表、代码结果包或其他正式产物以前，至少满足：

- 原始 Skill 和强制参考完整读取且哈希当前；
- 当前任务范围与排除项闭合；
- 到期原文要求都有真实锚点；
- 条件适用性已解析，负分支已有事实和负面义务证据；
- 计划、清单和测试没有替代原文；
- 上游语义、方法和求解证据已绑定当前目标。

任一项未完成就停止产物动作。

## 5. 交付门禁

`--phase delivery` 要求 `G0` 至 `G5` 全部完成，并重新核对：

- 每个原始来源、证据记录和最终目标的实际哈希；
- 每个适用要求的当前证据；
- 每个不适用要求的事实证据和负面义务检查；
- 全部要求依赖；
- 从原文到当前成果的完整正向审计。

只有验证器返回 `ok: true` 才允许交付。页数、清单全勾选、测试总数或“整体看起来不错”都不能代替逐条检查。

## 6. 回退

来源、用户裁决、输入、模型、代码、结果、图表、正文或审计目标发生变化时，从变化点沿直接依赖关系清除下游回执和正向审计，再按顺序重新验证。

不要只修改最终文件而沿用旧结果、旧图表或旧审计。

## 7. 对话内核验

简单、单步且不产生文件的问答不创建合同，但仍按已选 Skill 原文核验。任务若后来扩展为多步骤产物任务，必须在第一次产物动作前建立合同。
