# 权威、冲突与失效

## 1. 权威顺序

本技能不改变平台、系统、开发者和用户指令的优先级。在 Skill 工作流内部，要求只来自本轮实际选择的原始 `SKILL.md` 及其明确要求必读的参考文件。

合同、索引、计划、摘要、检查表、`artifact.md`、测试、夹具和审查报告均为 `record_only`。它们可以指向原文和记录证据，不能回答“原文没有写但我们决定增加什么要求”。

## 2. 完整读取

主执行者必须完整读取每个已选 Skill 和全部强制参考，并记录当前绝对路径与 SHA-256。以下做法不能代替完整读取：

- 只读摘要、目录、节选或搜索命中；
- 只接收代理总结；
- 复用历史任务、旧合同或旧记忆；
- 只运行测试而不回到原文。

每个阶段开始和最终审计都重新打开有关原文。阶段内可使用精确锚点导航，但锚点和原文哈希必须仍然匹配。

## 3. 冲突

发现冲突时：

1. 先应用平台、系统、开发者和用户指令优先级；
2. 检查是否读错版本、遗漏强制参考或使用过期哈希；
3. 区分真正冲突与不同条件下的分支；
4. 原始来源仍无法消解时，停止并向用户说明冲突原文、影响和需要的裁决；
5. 不要用计划、模板、清单、测试或当前成稿充当第三条规则。

派生材料与原文冲突时，原文立即胜出；冲突材料及其下游证据失效。

## 4. 条件分支

适用性由原始条件和当前事实共同决定：

- `applicable`：条件成立，必须完成原始要求并提供当前证据；
- `not_applicable`：条件不成立，必须有事实证据并检查原始要求规定的负面义务；
- `pending`：事实不足，不能通过门禁。

例如，没有附件数据时不进行虚构的数据清洗；同时要证明输入清单确实没有附件，并检查正式论文没有虚构清洗章节、过程或数据血缘。

## 5. 当前任务隔离

任务根和授权路径只来自本轮用户授权。合同复制或移动后，旧任务根不再自动有效。不得从旧题目、历史输出或其他任务继承路径。

明确排除的路径保持零访问：不读取、不枚举、不搜索、不预览、不哈希、不恢复缓存，也不通过代理间接读取。

## 6. 自动失效

以下变化会使直接相关要求及全部下游证据失效：

- 原始 Skill、强制参考或锚点哈希变化；
- 用户裁决改变语义、范围、适用性或目标；
- 授权根、排除路径、输入文件或交付目标变化；
- 模型、代码、结果、图表或正文目标变化；
- 共享证据删除、替换、过期或验证方法不可靠。

失效时清除受影响要求的证据引用和最终正向审计记录，使门禁重新变为待验证。不要改写原始要求或保留旧完成状态。

## 7. 失败关闭

缺失来源、锚点不匹配、哈希过期、未知依赖、越权路径、条件待定或证据不足都必须返回稳定错误并阻断到期门禁。无法证明时只能是 `pending` 或失败，不能猜成 `verified`。

专业工具能力不足时，按原始 Skill 允许的真实渲染、人工复核或用户确认补证；不要在中央锁中增加半套格式解析器或新的格式禁令。
