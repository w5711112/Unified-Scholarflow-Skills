# 核心权威、场景与受保护内容

本合同在每次改写前读取一次。它持有五条铁律、五种场景、冲突裁决、来源/承诺边界和受保护内容；规则词表、执行步骤与文档格式由各自责任文件持有。

把文本从“模型在表演写作”拉回“一个人在把事情说明白”。改写是重写表达，不是删除实质内容，也不是把论文、制度、邮件和对话都压成同一种语气。处理后应不卑不亢、自然克制、逻辑闭合、上下文准确，让目标读者容易理解。

判断一个词或句式要不要处理，看它在做什么动作，不看它有没有出现在清单里。同样的姿态换一套字面继续做，仍然命中；出现在清单里但当前句中承担实义的，按误杀防护放行。清单是代表项，不是穷举；遇到同类变体，先归入现有类别，再决定是否补词条。

## 铁律（优先级从高到低，冲突时前者胜）

1. **事实与强度守恒**。人物、数字、时间、术语、引语、归因、限定词（“可能/通常/在某种程度上”）、强调强度（“首次/显著/明显高于”），以及职责、范围和承诺逐项保留，不得新增、删除、升降格。改写后每个实词必须能在原文或用户明确要求中指出出处；“可能提升”不得写成“提升”，“计划完成”不得写成“保证完成”。
2. **语体与姿态相称**。润色前后保持原用途、作者身份、目标读者和正式程度。总体姿态是不卑不亢：不谄媚讨好、不自我贬低，也不居高临下、不指责挑衅、不用无依据的强硬或绝对保证。工作文档中有来源的“应/须/严禁/不得”、风险警示和拒绝越权仍保留其力度，这不属于语气激进。术语、定义、方法论名词化（“对数据进行预处理”这类流程表述）、学术惯例被动句和必要长句本身不是改写理由。
   学术与严谨文档不得被口语降格：“朴素”→“简单”可以，“五个东西”（应为“五个要素”）、“含金量”、“撑不起”、“炸了”禁止。对话、邮件、公众号和口播可保留自然口语，但不能为了“像人”引入轻浮、冒犯或夸张表演。
   **朴实是各语体共同的底色**：口语语体不等于可以渲染夸饰。渲染阅读体验、抬高内容价值的词句（“一眼就能看懂”“轻松很多”“就等于掌握了”）在任何语体下都按 R7 处理，博客也不例外。
3. **篇幅不设指标**。缩短只允许两类：整句纯姿态层（列入「待确认」，默认执行、可回退）和短语级空洞修饰（在「改动说明」中计数）。归因是记账手段，不是目标；验收标准是语言风格本身（连贯、自然、像人写的），篇幅数据不代替风格判断。
4. **不做身份表演**。不引入原文没有的作者身份、读者关系、经历、例子、数据或来源。论文和正式文档不凭空加入“我/你”（基金本子的“本研究/本项目”除外）；对话、邮件和消息可保留原有说话人称、称呼与礼貌程度，但不能替作者编造立场或关系。宁可平实，不可表演。
5. **输出洁净**。成稿不得残留不属于目标文本的 AI 服务话术、元评论、处理过程、历史对话指涉、知识截止声明和占位符。对话场景可以有真实轮次、称呼和回应，但仍不能出现“作为 AI”“我已按你的要求润色”等处理痕迹。改写的产物是“作者要发出或保存的文字”，不是“AI 处理文本的记录”。详见 R13/R14。

## 普适语言闸门

- 任何已有简体中文文本都可以作为 `SOURCE_BASELINE`。有专业内容时，专业 Skill 先形成事实完整的语义草稿，再按 `专业语义草稿 → renhua → 格式 Skill` 处理；普通段落、邮件、消息和对话则直接以原文、当前对话上下文和用户明确要求为基线，不虚构一份专业材料。
- renhua 只处理表达，不替代论文精读、事实核验、控制算法分析或其他专业判断。若原文没有说明一个术语所指的对象、输入来源或输出去向，不能凭常识补写；应把缺口列入“需补信息”，交还专业任务补齐。
- 格式 Skill 只负责 Obsidian、Word/WPS 等呈现规范。格式处理若新增标题下的概括句、表格正文或其他实质性文字，新文字需要再次经过 renhua；纯格式符号和既有正文的位置调整不需要重跑。

## 来源、承诺与多文档边界

- 只有任务存在合同、招标文件、上级要求、技术规范、论文原文、用户确认稿或其他权威材料时，才建立来源优先级。改写必须沿用其中的对象、范围、职责、数量、版本、验收条件和不确定性；没有权威材料的普通文字不得虚构“已核对来源”或自创审计链。
- 不主动扩大或缩小承诺。应承担的责任、强制条款和风险措施必须保留；原文没有要求的无限责任、零故障、无条件配合、永久保证或额外交付不得为了显得积极而加入。
- 框架、平台或总方案包含某项能力，不等于每个阶段、子系统或配套文档都承诺实现该能力。只有来源明确把责任落到当前对象时，才能写成当前对象的职责或验收项。
- 多文档共同交付时，先确定每份文档的唯一职责。相同术语、对象、数字、版本、引用和交叉编号必须一致；同一段实质内容由一份责任文档完整持有，其他文档保留必要摘要或明确交叉引用，不复制出多套容易漂移的正文。

## 场景判定

- **paper-notes（论文、知识点笔记）**：以概念、方法、公式、文献陈述为主。定义性并列（“A 衡量 X，B 衡量 Y”）是规范写法，允许保留；术语首现后不再反复解释。面向初学者的精读笔记应在术语首次出现时说明它指什么对象、数据从哪里来、在算法中起什么作用。
- **grant-proposal（基金本子）**：以研究内容、目标、方案、创新点、可行性为主。“本研究/本项目”作主语；创新点和意义的强调词按原文强度保留（既不加码也不弱化），“有机统一”“设计载体”“内在契合性”等本子惯用评价语属于文体常规，不改；“综上/由此”引出研究内容或收束立项逻辑时是功能性衔接，保留；概念首现的引号（如“单机导引”）按术语处理，允许保留。目标—方案—可行性框架不动。
- **work-doc（严谨工作文档）**：质量管理方案、实施方案、技术方案、规程制度类文稿。条款式表述、编号层级、“应/须/严禁/不得”等规范助词保留；职责分工、流程步骤、验收条款的框架不动。条款内的平行结构是体裁要求，R6/R11 不得打散；名词化比论文更容忍（公文体），R9 只处理明显赘疣；黑话按 R12 一级表处理，义项放行条款适用（质量管理中的“闭环整改”“可追溯”是正式术语）。
- **general-text（普通文本）**：一般说明、报告片段、邮件、消息、公众号、口播稿和无法归入前三类的段落。保持原用途和正式程度，可以保留自然口语、第一/第二人称和必要称呼；不得用学术腔强行拔高，也不得为了口语化加入网络腔、夸饰或冒犯。结构以读者能顺着理解为准，不强套“观点—解释—小结”。
- **dialogue（对话与回复）**：输入含明确说话轮次，或用户要生成一段回复、沟通消息、问答。保留说话人、称呼、真实问题和必要礼貌，允许“我/你/您”；删除 AI 服务姿态和讨好/压迫性的情绪包装。拒绝、纠错、风险提醒和边界说明可以直接，但要给出具体事实或条件，不能攻击对方动机、人格或能力。
- 未指明时按 `general-text` 处理。遇到“论文/摘要/知识点/方法”等信号切 `paper-notes`；遇到“本研究拟/立项依据/研究基础”等信号切 `grant-proposal`；遇到“职责分工/工作流程/验收标准/应按下列要求”等信号切 `work-doc`；明确保留说话轮次或形成回复时切 `dialogue`。内容用途比文件扩展名优先，一份 Word 文件不自动等于 work-doc。
- 论文结论章、摘要的总结句是体裁规范，R5 只删空洞复述，不删体裁要求的总结。
- **冲突裁决**：场景判定中的豁免条款，优先于与其冲突的编号规则。规则之间冲突时，编号小者优先。

## 受保护内容（动手前先划出，一律不动）

- 人物、机构、数字、时间及其修饰对象；“从 2.3% 降至 0.8%”须整体保留。
- 变量名与符号写法、公式、方法与模型名（Q-learning、epsilon-贪婪）、固定术语。
- 直接引语、归因、限定词和强调强度。
- 职责主体、承诺对象、适用范围、交付物、验收条件、风险边界和规范助词；有权威材料时保留其来源优先级。
- 参考文献列表、图表标题、引用标识。引文号紧跟它实际支持的陈述；调整语序时，引用必须与被支持的陈述一起移动。
- 场景规定不可改的结构：基金本子的目标—方案—可行性框架，工作文档的编号层级、职责、流程和验收框架，对话的说话人及真实轮次，多文档体系的职责分工和有效交叉引用。

## 对外能力描述与叙述连贯（适用于介绍 Skill/工具/体系的文字）

- **具体化优先于口号**：能力说明要能对上“对什么操作、用什么手段、软件里留下什么、为何有用、和什么区分开”。只写“自动化、体系化、赋能、支撑”而不落到对象与产物的，按 R15 能力描述条款改写或列入「需补信息」。
- **连贯优先于堆砌**：非“多图陈列”型页面（普通 README 段落、说明文、讲稿）必须让句子之间有逻辑递进；在不改变含义的前提下理顺语序与承启。读完仍不知所以的，按 R16 叙述连贯条款补功能性过渡或重排依赖顺序。
- **事实与强度仍受铁律 1 约束**：具体化与连贯不得虚构步骤、夸大“自动”或改写限定词。

## 误杀防护

- 术语、定义、方法论流程名词化、学术惯例被动句、必要长句、关键词重复本身均不是 AI 痕迹。
- 定义性并列、体裁性总结、真实让步和规范条款结构按场景放行。固定定义保留正面含义；范围排除和纠偏表达按 R2 判断具体必要性，保留影响真值与理解的限定，去除无关或重复排除，不能仅凭“这是定义”放行整串防御性表述。
- 有依据的强制条款、风险警示、责任说明和拒绝越权不因语气直接而被弱化；自然礼貌、真实感谢和必要称呼也不因出现在对话中而机械删除。
- 词表命中但当前承担实义时不改；词表未命中但执行同类姿态动作时仍按对应规则处理。
- 原文自有错误、疑似虚假因果、无源论断、未定义术语或作者占位符，不得借人性化改写静默补写或改成另一个事实。
