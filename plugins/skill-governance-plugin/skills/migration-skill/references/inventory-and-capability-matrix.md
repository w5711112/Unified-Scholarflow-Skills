# 迁移对象、能力矩阵与标准流程

## 迁移对象盘点

开始前完整读取源 Skill 及其直接引用资源，并将以下清单写入 `MIGRATION_BASELINE`：

| 层 | 必须盘点 | 迁移判断 |
|---|---|---|
| 指令 | `SKILL.md`、触发描述、硬门槛、退出条件 | 原样保留语义；只调整宿主语法 |
| 资源 | `references/`、`assets/`、模板 | 复制并校验路径和编码 |
| 执行 | `scripts/`、命令、依赖、运行时版本 | 优先保留平台无关核心，另建适配层 |
| 接口 | 浏览器、PDF、Zotero、MCP、应用连接器 | 进入能力矩阵，逐项寻找替代 |
| 状态 | 数据文件、数据库、任务进度、缓存 | 区分可移植事实和宿主临时状态 |
| 验证 | 单元测试、样例、验收场景、哈希 | 必须随迁移包保留 |
| 配置 | 示例配置、路径、环境变量 | 使用目标机配置，不复制秘密 |

如果漏掉 scripts、references、assets、fixtures 和 tests，只能称为“近似提示词”，不能称为同一个 Skill。

## 能力矩阵

为每项平台专属能力形成一条 `CAPABILITY_MAP` 记录；不允许只写“目标模型应该也能做到”。

| 源能力 | 真实用途 | 目标 Agent 替代 | 验证方法 | 缺失时降级 |
|---|---|---|---|---|
| 网页浏览 | 打开官方来源并保留证据 | Codex Browser、WebFetch、Kimi Web 或受控浏览器 | 打开指定页面并提取可核对字段 | 只做本地审计，不新增外部事实 |
| PDF 阅读 | 读取正文、公式、图表和实验 | 目标环境 PDF 工具或可验证文本/图像管线 | 逐页核对页数、公式、表图 | 标为未读全文，不写全文结论 |
| Shell/Python | 审计、转换和测试 | 目标 Agent 的终端或脚本执行器 | 运行固定测试命令 | 人工执行并回传原始结果 |
| 外部应用写入 | Zotero、Obsidian 或其他应用操作 | 对应连接器、公开 API 或受控本地脚本 | 写前备份、写后重读 | 只生成 dry-run，不宣称已写入 |
| 自动调度 | 周期任务 | Codex automation、cron、Task Scheduler 等 | 触发一次可恢复单周期 | 改为手动入口 |

工具名称可以变化，但决策顺序、证据等级、备份要求和失败条件不能变化。

## 标准迁移流程

1. **冻结源基线**：记录源 Skill 版本、文件清单、SHA-256、测试命令和已知外部状态。
2. **划分边界**：列出平台无关核心、宿主适配、工作区数据和秘密。
3. **复制核心**：保留 `SKILL.md`、scripts、references、assets、fixtures 和 tests 的相对关系。
4. **建立适配层**：只在目标宿主目录或 manifest 中映射工具、命令、路径和调度方式。
5. **处理配置**：从 `config.example` 生成目标配置；绝不复制 token、cookie、登录态或用户认证文件。
6. **实现降级**：每个缺失能力都写清能做什么、不能做什么和如何恢复完整能力。
7. **逐层验收**：先文件，再能力，最后用真实任务验证行为。
8. **记录差异**：输出新增适配文件、未具备能力、验证结果和后续维护入口。
