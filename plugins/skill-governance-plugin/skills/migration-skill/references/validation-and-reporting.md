# 三层验收与迁移报告

三层结果统一写入 `MIGRATION_ACCEPTANCE`。每一 distinct risk 在对应层只使用一份当前权威证据；进入下一层引用已有结果，不重复同一检查。

## 文件级验收

- 目标文件清单完整，文本编码和相对路径有效。
- 原样复制的核心文件 SHA-256 一致。
- `SKILL.md` frontmatter 可解析，名称与目录一致。
- scripts、references、assets、fixtures 和 tests 没有遗漏。
- 可阅读指南与对应 `SKILL.md` 互为字节级镜像。

## 能力级验收

- 能力矩阵每一项都实际执行过验证命令或真实只读操作。
- 平台专属工具有明确替代，输入输出满足原合同。
- 缺失能力触发预定降级，没有静默跳过。
- 写入型能力具备备份、dry-run 和写后重读验证。

## 行为级验收

至少选择一个正常场景、一个边界场景和一个失败场景：

1. 正常场景完成预期产物并通过测试。
2. 证据或输入不完整时，目标 Agent 按原 Skill 的硬门槛停止。
3. 目标能力缺失时，只执行允许的降级流程并明确报告。
4. 输出事实、推断和建议的边界与源 Skill 一致。
5. 重新运行同一任务不会制造重复数据或不可解释漂移。

## 迁移报告模板

> [!summary]- **迁移结果**
> - **源 Skill**：名称、版本、基线哈希
> - **目标宿主**：模型、Agent、操作系统、运行时
> - **直接复制**：文件与资源
> - **平台适配**：新增或替换的接口
> - **能力缺口**：缺失项与降级行为
> - **验证证据**：文件级、能力级、行为级结果
> - **仍需用户处理**：授权、安装或配置

## 常见错误

- 只复制 `SKILL.md`，遗漏脚本、引用和测试。
- 把源 Agent 的工具名当成平台无关标准。
- 为每个宿主复制并分别修改核心代码，导致长期漂移。
- 把“文件存在”当作“外部能力已经可用”。
- 没有实际运行失败场景就宣称行为等价。
- 把秘密、登录态或绝对用户路径写进迁移文件。
- 用巨型 Base64 源码归档代替清晰的 Skill、版本控制和测试。
