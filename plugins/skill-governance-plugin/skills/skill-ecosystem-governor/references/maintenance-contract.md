# 有界维护、同步与补跑

本分支由用户批准的维护计划触发。它是执行后退出的一次任务，不建立驻留监听器。组件位置与镜像登记在唯一 ecosystem-registry.json；运行状态仅记录已同步目标哈希、上次成功时间及必要恢复信息，不成为规则来源。

## 同步与冲突

1. 解析注册表，冻结当前来源哈希，检查明确登记的源文件引用。
2. 完整指南由 SKILL.md 和全部 references 确定性生成；源入口先于参考，内部链接使用实际存在的定位锚点。镜像包逐文件比较；可读指南按生成结果比较，不要求展开后的指南等于单个入口文件。
3. 总览的自动区直接取当前来源说明并链接完整规则。人工职责说明变化须在受控发布时核对，不得仅刷新 source marker 掩盖文字过期。不能自动证明的人工说明差异提交审核。
4. 同一批输出先全部生成、检查，再写入。已有输出必须与上次核验哈希一致；人工改过、同时改过或来源在执行期间变化时停止，不反向覆盖源文件。
5. 写入前留恢复副本并逐文件读回，失败恢复已写项；恢复失败保留 journal 并报警。`--adopt` 仅供人工核对后建立目标基线，定时任务不得用它绕过冲突。
6. 无变化不改内容或 mtime。正常巡检只更新一个到期状态，不产生逐次成功报告。运行恢复副本由 hygiene 根据有效发布、引用和保留期限处理。

脚本当前自动处理完整指南、注册 mirror_packages 和总览自动区。未知引用目标、人工职责说明、插件安装版本与源语义修改需要受控审核和发布，不能标记成已自动修复。维护不自动发布 ecosystem lock；发布仍通过 owner/consumer 测试和全量审计。

## 触发与恢复

正常发布同步受影响组件；每日北京时间 02:00 补查。Windows 计划任务启用错过后运行、登录后到期检查、单实例和有限重试。电脑关机时不会执行，恢复可用后补跑；应实测宿主、账户权限、休眠和登录条件，再报告实际保障范围。

同步使用跨进程互斥；截止时间以最近成功运行记录为准，失败不推进。检测到系统时钟回退时停止说明。已有每周只读审计应与新维护统筹，避免重复通知。无变化保持安静，有实际修复、冲突、失败或需要用户决策时报告。

清理由 workspace-hygiene 执行，先 dry-run。保留所有 PPT Skill 版本和共享素材；不按最大版本号或文件时间自动认定旧文件无用。候选池审核记录、最新已验收构建依赖、用户文件和活动任务均受保护。定时任务不得改变全局权限、安装软件、发布 GitHub 或执行第三方脚本。
