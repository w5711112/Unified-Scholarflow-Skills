# 通用化、依赖与冗余裁决

## 1. 逐条分类

| 分类 | 判断 | 公开化动作 |
| --- | --- | --- |
| `invariant` | 决定质量、安全、严谨性或可复核性 | 原义保留，允许换位置但不降低强度 |
| `configurable` | 取决于用户课题、环境或工具选择 | 移入配置，写明类型、必填、默认和校验 |
| `example` | 帮助理解但不应约束所有使用者 | 标明示例，可提供无人机/RL/VLM 等不同样例 |
| `redundant-candidate` | 可能被替代、废弃或重复 | 进入证据裁决，不能直接删除 |

白名单条目可以由使用者配置，但原 Skill 若规定数量下限、来源等级或覆盖面，公开版必须保留这些约束。不能把“至少 N 个”改成“若干个”，也不能用一个短示例列表冒充完整默认规则。

## 2. 通用配置

推荐配置至少表达：研究主题、任务类型、关键词组、排除词、来源白名单、来源分层、时间范围、语言、输出格式、集成方式和本地路径。配置仅保存非秘密值；秘密用环境变量名引用。

配置的示例值不得悄悄成为运行默认。工具若找不到必填配置，应明确停止并列出缺项，而不是回退到作者的无人机或强化学习主题。

## 3. 多 Skill 依赖

发布集合中每个 Skill 都应声明：提供的能力、消费的上游、调用条件、输入/输出接口、共享配置、镜像同步规则和失败传播。改名时更新所有调用方、README、示例和清单，并用全文引用检查确认没有旧名称残留。

若某 Skill 只有在另一 Skill 存在时才工作，README 必须把它标为硬依赖；可降级运行的标为可选依赖，并写清降级行为。

## 4. 冗余证明

机械生成物直接排除。语义文件只有满足以下证据才可加入 `confirmed_redundant`：

1. 静态引用图无入边；
2. 跨 Skill 调用图无入边；
3. 不属于运行时约定、插件发现目录、模板或镜像源；
4. 内容已被当前权威文件完整取代，或明确是历史输出；
5. 删除后测试、结构验证和代表性流程仍通过；
6. 删除理由记录到整理映射。

任一项未知则保留为 `unresolved_orphan` 并阻断发布。确实需要但无法静态引用的文件放入 `keep_unreferenced`，同时记录用途。

## 5. 禁止的“精简”

- 合并看似相近但适用条件不同的规则；
- 删除数值、例外、负面义务或停止条件；
- 用 README 摘要替代原始权威参考；
- 把多个 Skill 的共享文件复制成多份并各自维护；
- 保留 `draft-v2-final-new.md` 等历史链让用户自行判断。
