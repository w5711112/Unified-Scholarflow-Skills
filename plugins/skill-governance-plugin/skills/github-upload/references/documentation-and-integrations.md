# 公开文档与集成合同

## 轻量 README

普通单 Skill 只需要与实物一致的简洁说明：用途、安装、调用方式、配置、实际依赖入口、隐私提醒和已知限制。没有相关集成时不要生成空泛的 Codex、Zotero、Obsidian 或桌面软件章节。下面的完整合同仅适用于确实包含这些能力或用户要求正式发布文档的包。

若工作流串联浏览器、Zotero、Codex 和 Obsidian，四者都属于必要复现前提。README 必须给出各端准确插件/扩展名称、安装方式、权限、连接配置、数据去向和最小端到端验证；不能只写“需要 Zotero/Obsidian”而省略联动步骤。

## README 必备内容

1. 一句话用途和适用/不适用场景；
2. 包内目录树及各文件职责；
3. Skill 之间的调用关系和数据流；
4. 操作系统、Python/Node、Git、桌面软件和插件依赖；
5. 安装、更新、卸载和最小验证命令；
6. 所有配置字段、默认值、示例和秘密注入方式；
7. 专业规则、不变量、可配置项和停止条件；
8. 最小示例与完整工作流；
9. 集成设置、权限和故障排查；
10. 隐私安全、已知限制、版本兼容性和许可证。

README 描述必须与发布包实物一致。未验证的平台、版本或插件不得声称“支持”；改用“未验证”并给出验证方法。

## Codex

- 说明 Skill 目录必须包含 `SKILL.md`，并给出用户级安装位置示例 `~/.agents/skills/<skill-name>/`；Windows 示例使用可移植占位路径，不写作者用户名。
- 若含 `agents/openai.yaml`，说明它只提供界面元数据和调用策略，不替代 `SKILL.md`。
- 指明触发语句、显式 `$skill-name` 用法、输入要求和授权边界。

## Zotero

优先明确所用适配器：

- 本地读取：Zotero 桌面端本地 API，用户需在高级设置允许本机应用通信；基址通常是 `http://localhost:23119/api/`。读取无需 Web API Key，但端口不得对外暴露。
- 本地写入：Zotero 10+ 在运行时请求本地写授权，并处理 `Zotero-Server-ID`、版本前置条件和授权失败。
- 云端库：使用 Zotero Web API v3，Key 从环境变量或秘密存储注入，说明用户/群组库 ID、权限和限流处理。

不得直接读取或复制 `zotero.sqlite` 作为常规集成方案。README 应给出连通性探测、典型 401/403/412/428/429 处理和最小权限原则。

## Obsidian

明确选择以下一种或多种方式：

- 文件系统：向用户配置的 Vault 相对路径写 Markdown；先验证目标位于授权 Vault 根内，避免目录穿越和覆盖。
- Obsidian URI：用 `obsidian://open`、`new` 或 `search` 打开/创建/搜索；对 Vault、文件名和正文参数做 URI 编码。
- 第三方 REST 插件：必须写明插件名称、版本、端点、权限和认证方式；不要把它描述成 Obsidian 原生接口。

## Codex → Zotero → Obsidian 最小链路

1. Codex Skill 接收主题和用户配置；
2. Zotero 适配器检索元数据/附件，返回稳定 item key 和来源信息；
3. Skill 生成内容及来源映射；
4. Obsidian 适配器写入 Vault 相对路径；
5. 验证笔记存在、引用 key 可回溯、重复运行满足约定的幂等策略。

README 必须分别列出三段的输入、输出、失败码、权限和数据去向，不能只说“已打通”。
