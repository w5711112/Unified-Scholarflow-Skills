# 治理模式发布合同

本合同只用于完整治理模式。普通单 Skill 的隐私清理与文档补齐使用 `SKILL.md` 中的轻量工作流，不需要建立本合同的五对象证据链。

## 1. 输入闭合

只接受用户本轮授权的源根。对每个 Skill 记录：绝对源路径、`SKILL.md`、强制参考、脚本、资产、说明镜像、被调用关系和 SHA-256。多 Skill 任务把它们视为一个发布集合，不逐个孤立清理。

若源包存在 `AGENTS.md`、`CLAUDE.md`、插件清单或维护说明，先判断它们是否约束发布。不能读取的必需源、来源哈希漂移和范围不明均为停止条件。

## 2. 五阶段，只验证一次

### A. 基线

创建 `SOURCE_BASELINE`，冻结原始文件清单和哈希。源包默认只读；发布区必须在源根之外，且不得复用上次任务的旧暂存区。

### B. 依赖

创建 `DEPENDENCY_GRAPH`：

- `SKILL.md → references/scripts/assets/agents` 文件引用；
- `Skill A → Skill B` 显式或约定调用；
- 主包与中文指南、草稿包、插件缓存等镜像；
- Python 包、命令行程序、桌面软件、API、环境变量和权限。

文件没有静态链接不等于没有依赖。检查动态路径、文件名约定、脚本参数、模板复制和运行时发现。

### C. 整理

创建 `SANITIZATION_MAP`，每个变化记录：源位置、分类、公开包位置、动作、理由、功能影响和验证方法。允许动作只有 `preserve`、`parameterize`、`replace-with-example`、`remove-confirmed-redundant`、`redact-secret`。

### D. 发布包

先用工具建立隔离副本，再在副本中编辑。包必须包含实际需要的 Skill 文件、公开 README、示例配置、依赖说明和许可证信息；不得为了“看起来完整”添加无调用占位文件。

### E. 交付

对 `DELIVERY_GATE` 一次性检查：

1. 原始不变量逐条在公开包中找到；
2. 配置项均有默认/示例、类型、是否必填和验证方式；
3. 秘密、个人信息、本机路径和内部地址无阻断项；
4. 依赖图闭合，未裁决孤儿为零；
5. README 与实际文件、命令和兼容性一致；
6. 本地测试和结构验证通过；
7. 远程确认字段完整且仍是当前用户意图。

不要让隐私、README、泛化和 GitHub 子流程分别重扫全部文件。它们把发现写入同一对象，最终集中判定。

## 3. 变化失效

源内容变化使基线及全部下游失效；调用关系变化使依赖图及下游失效；公开副本变化只使受影响整理记录、发布包和交付门禁失效；仓库/分支/许可证变化只使远程确认和交付门禁失效。

## 4. 输出

本地阶段交付：隔离发布包、`release-manifest.json`、`audit-report.json`、泛化/冗余裁决记录和待确认项。远程阶段另交付：提交哈希、仓库路径、分支、发布 URL，以及实际推送后的文件树核验。
