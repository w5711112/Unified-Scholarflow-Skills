# 隐私与秘密规则

## 轻量模式边界

轻量模式只自动处理可机械识别的高风险内容：凭据、真实邮箱、用户目录绝对路径、`.env*`、日志、备份和运行数据库。领域主题、搜索偏好、阈值、白名单逻辑和示例默认保留；只有用户明确列入 `redactions` 的词才替换。扫描通过表示“未发现已知模式”，不是对所有二进制或自然语言隐私作绝对保证。

## 阻断项

- API Key、PAT、OAuth Token、会话 Cookie、密码、私钥、证书私钥和连接串；
- `.env*`、凭据文件、SSH 配置、云服务配置和带认证参数的 URL；
- 个人用户名、真实邮箱、手机号、地址、本机绝对路径、Vault 名称或 ID、Zotero 用户/库 ID、内网主机、共享盘和未公开仓库地址；
- 运行日志、缓存、错误转储、历史测试输出中包含的上述内容。

示例必须使用明显不可用的占位符，例如 `${ZOTERO_API_KEY}`、`YOUR_LIBRARY_ID`、`OWNER/REPOSITORY` 和 `C:/path/to/vault`。不要使用长度和格式都像真实凭据的假 Token。

## 三层检查

1. `release_tool.py audit` 做确定性模式检查；
2. 若环境已有 `gitleaks` 等工具，对发布工作树和待推送 Git 历史再扫描；
3. 人工检查配置、截图、示例输出、二进制附件和最终 diff。

正则没有命中只表示“未发现已知模式”，不能表述为绝对安全。GitHub push protection 是最后一道补充，不代替本地检查。

## 已暴露秘密

若真实凭据曾进入提交或远程：先停止发布，轮换/撤销凭据，再按 GitHub 官方敏感数据清除流程处理历史。只删除当前文件不足以消除历史泄漏。不要把凭据内容复制进审计报告；只记录类型、文件和行号。

## 集成安全

- Zotero Web API Key 只通过环境变量或用户的秘密存储提供；不要写入 Skill、README 或示例。
- Zotero 本地 API 的读取端口只绑定本机使用，不做端口转发；写入授权在运行时由用户批准。
- Obsidian Vault 使用参数或环境变量定位；公开文档不得包含真实 Vault 绝对路径或 ID。
- GitHub 认证使用 `gh auth login`、系统凭据管理器或环境秘密；Skill 不读取、回显或保存 Token。
