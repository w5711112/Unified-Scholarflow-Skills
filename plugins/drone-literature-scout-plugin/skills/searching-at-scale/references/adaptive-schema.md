# 动态字段与证据原子合同

按需在页面抽样、字段清单稳定、对象合并或时间序列计算前读取。股票、商品、酒店和展会只是样例，不是类型白名单。

## `EvidenceAtom` 精确字段

| 字段 | 含义 |
| --- | --- |
| `entity_id` | 稳定对象标识；优先平台 ID、官方 ID 或规范化复合键 |
| `entity_type` | 商品、卖家、酒店、活动、机构、文件、证券等运行时类型 |
| `field_name` | 本任务发现的字段名 |
| `raw_value` | 页面/API 原始展示值，不覆盖 |
| `normalized_value` | 统一日期、货币、单位、枚举后的值 |
| `unit` | 规范化单位；不适用时为 `None` |
| `valid_at` | 信息实际对应时间；未知时为 `None` |
| `observed_at` | 本轮采集时间 |
| `source_url` | 可回溯 HTTP(S) 来源 |
| `source_grade` | `A`–`E` 来源等级 |
| `derived` | 是否为派生值 |
| `derivation` | 派生公式、窗口、参数和口径；原始值时为 `None` |
| `confidence` | 0–1 的证据置信度，不等同推荐度 |
| `missing_reason` | 未公开、需登录、访问受限、口径缺失或无法核验；有值时为 `None` |

`raw_value` 与 `normalized_value` 使用可冻结的 JSON 形状；聚合后保持不可变，避免后续页面处理改写已采集证据。

## 对象、字段、关系与时间序列发现

1. 从不同来源类别和页面类型抽样，不让单一模板定义全部字段。
2. 识别对象类型、稳定身份、候选字段、对象关系和时间轴；字段含义相同再统一，不因名称相似强行合并。
3. 连续多轮不再发现新字段后稳定本任务 schema；schema 稳定只表示字段清单收敛，不是 URL 发现停止条件。
4. 对相关对象尽量补齐公开/授权字段，保留每个值的来源与时间；缺失不写零、不写空事实。
5. 用稳定主页、平台 ID 或官方标识合并对象。昵称、显示名或相近标题不能单独作为同一性依据。
6. 关系单独建模，如卖家—商品、主办方—展会、酒店—房价、公司—证券；关系本身也需要来源。
7. 时间序列按日期排序并保留数据集身份、交易/自然日历、调整方式、缺失日与异常事件。

## 平台对象示例

商品可按页面实际展示采集：标题、现价/原价、发布时间、品牌、型号、尺码、颜色、配置、成色、包邮、所在地、交付方式、详情全文、图片数量、交易凭证图片、想要/浏览/留言、状态和 URL。

卖家可按公开主页采集：昵称、稳定主页/平台 ID、信用等级、评价标签、买入/卖出/交易数量、评价数量、在售/已售、动态数量、页面公开的 IP 属地、注册/活跃时间和相关商品。没有公开展示或需要更高权限的字段写 `missing_reason`，不得猜测、绕权或仅凭昵称合并。

## 原始值与派生值

- 原始行情保留日期、OHLC、成交量/额、换手率、量比、涨跌额/幅及来源口径。
- MA、Wilder RSI、KDJ 等由 `compute_timeseries.py` 计算时，`derived=True`，并记录窗口、种子、公式、复权方式、输入序列身份和数据日期。
- 计算结果不能回写为来源原始值；窗口不足输出缺失并说明原因。停牌、除权除息和缺失交易日单独标记。
- 货币换算、单位换算、排序分数和推荐判断同样属于派生值；保留输入、公式和采集时间。

使用 `aggregate_evidence.py` 按 `entity_id` 与 `field_name` 无损聚合多个证据原子。冲突证据并存，由严格核验层决定呈现，不在聚合时静默覆盖。
