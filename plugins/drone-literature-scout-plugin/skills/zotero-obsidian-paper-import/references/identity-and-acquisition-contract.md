# 论文身份与合法获取合同

本文件由 `SKILL.md` 直接按任务类型加载，拥有固定批次、DOI 身份与 PDF 合法获取的详细要求。

## 核心目标

把 Obsidian 的论文索引作为输入事实源，把 Zotero 作为 PDF、元数据和批注事实源。所有 DOI、正式出版页面、PDF 和 Zotero 附件 key 都必须经过身份核验；任何不确定项宁可暂挂，不得猜 DOI、猜文件版本或猜 Zotero URI

## 固定范围与主键

- 处理 `01-核心论文精读.md` 时，默认按论文编号顺序处理
- 本项目当前批次从第 12 条到第 102 条，共 91 条；第 1–11 条不得重新创建或重复下载
- 以 Obsidian 论文编号作为批处理主键；DOI 只作为去重键之一
- 每条状态保存到 `skill-with-plugin/运行数据/`，不得只依赖 Markdown 中的显示文本
- 先检查编号连续性、重复编号、嵌套标题和来源行，再进行网络请求

## DOI 与身份核验

1. 规范化 DOI：去掉 `https://doi.org/`、首尾空格和句末标点，比较时不区分大小写
2. 已有 DOI：查询 Crossref，访问 DOI 落地页和正式出版页，至少核对标题、第一作者、venue、年份中的三项
3. 缺 DOI：依次使用精确标题、标题+第一作者、标题+venue+年份检索 Crossref、正式出版社页和正式会议 proceedings
4. 只接受能交叉匹配标题、作者、venue、年份的 DOI
5. DOI 指向勘误、社论、摘要、预印本或不同版本时拒绝自动接受
6. 把“暂未找到”“确认无公开 DOI”“候选 DOI 待人工核验”分成不同状态
7. 不把 arXiv 编号、Paper ID、URL 片段、BibTeX citation key 或年份当作 DOI
8. 2026 年记录允许 DOI 尚未分配，但必须保留正式会议/出版社页面和检索证据

## PDF 获取与验证

按以下优先级尝试：

1. 笔记中的正式 PDF URL
2. 正式出版社或会议 PDF
3. DOI 落地页解析出的 PDF
4. 合法开放获取地址
5. 已登录浏览器/Connector 中可访问的 IEEE、Nature 或 Science 页面

遵守以下硬规则：

- 不绕过付费墙、验证码、机构访问控制或版权限制
- IEEE 可利用本机现有登录状态；Nature、Science 和会议登录状态不得假定可用
- 下载前后记录 URL、HTTP 状态、Content-Type、文件大小和时间
- 文件必须以 `%PDF-` 开头，不能是 HTML 登录页、验证码页、摘要页、Snapshot 或补充材料
- 能从 PDF 文本或来源元数据确认题名/版本时才标记为已验证
- 默认新增导入必须先取得并核验正式 PDF；下载失败进入 `pdf_download_failed`，保留待办，不提前创建父条目。仅用户另行明确要求“只建元数据”时才可走单独批准的元数据流程，默认导入脚本不提供绕过开关
- 不反复高速重试；遵守服务方限速，遇到 429/403/登录页立即退避或转浏览器流程

## 已有 PDF 与正式版本冲突

用户要求使用现有 PDF 或不重新下载时，先核验现有文件的题名、作者、版本、页数和 SHA-256。文件确为正式版即可复用，跳过网络获取；但仍要完成 Zotero 父条目、stored attachment、元数据和回链所需的全部读写/读回门。

若现有 Zotero 条目挂的是预印本、旧作者列表、错误/残缺版本，而正式版已经可用，建立 `VERSION_RECONCILIATION`：记录旧条目/附件身份和可恢复保留状态，核验正式来源，把正式 PDF 接入正确父条目并更新元数据，再从本机 API 读回。不能因旧附件可打开就继续基于旧版生成页码、批注或回链。

## 正式版本前置核验与单版本导入

- 新论文先确定唯一目标出版版本，再核验实际 PDF 的题名、作者、venue、年份、正文身份和版本；摘要、补充材料、预印本与期刊扩展版分别判断。正式版本优先于 arXiv 等预印本；只找到预印本时保持待核验，不把它改写成正式出版物
- 在同一份 `IDENTITY_EVIDENCE` 中保存正式来源、核验时间、判断依据、即将写入的完整书目信息、PDF 来源及 SHA-256。脚本字段 `publication_verification` 对应 `publication`、`source_url`、`reviewed_at`、`identity_basis` 和 `pdf`；`pdf` 包含 `path`、`sha256`、`source_url`、`version: version_of_record`
- `publication` 对齐即将发送的 `title`、`itemType`、`creators`、`date`、`DOI`、`publicationTitle`、`proceedingsTitle`、`url`；其中 DOI 缺失须保留原 DOI 状态，不为通过校验编造。核验记录负责绑定专业判断，字段齐全或哈希匹配本身不能证明出版身份正确
- 写前核验记录、元数据或 PDF 不一致即阻断。一次新增只写入一个已确定的父条目和一份已核验的正文 PDF；不并行导入预印本与正式版，不把镜像下载产生的副本作为第二份正文附件
- 复用同一门内的身份核验证据；文件、元数据或目标版本变化才重新核验受影响内容。上传紧前只做文件一致性检查，不重新搜索已确认且未变化的正式来源
