# 论文身份与合法获取合同

本文件由 `SKILL.md` 直接按任务类型加载，拥有固定批次、DOI 身份与 PDF 合法获取的详细要求。

## 核心目标

把 Obsidian 的论文索引作为输入事实源，把 Zotero 作为 PDF、元数据和批注事实源。所有 DOI、正式出版页面、PDF 和 Zotero 附件 key 都必须经过身份核验；任何不确定项宁可暂挂，不得猜 DOI、猜文件版本或猜 Zotero URI

## 固定范围与主键

- 处理 `01-核心论文精读.md` 时，默认按论文编号顺序处理
- 本项目当前批次从第 12 条到第 102 条，共 91 条；第 1–11 条不得重新创建或重复下载
- 以 Obsidian 论文编号作为批处理主键；DOI 只作为去重键之一
- 每条状态保存到 `skill-with-plugin/运行数据/`，不得只依赖 Markdown 中的显示文本
- 先检查编号连续性、重复编号、嵌套标题和来源行，再进行网络请求

## DOI 与身份核验

1. 规范化 DOI：去掉 `https://doi.org/`、首尾空格和句末标点，比较时不区分大小写
2. 已有 DOI：查询 Crossref，访问 DOI 落地页和正式出版页，至少核对标题、第一作者、venue、年份中的三项
3. 缺 DOI：依次使用精确标题、标题+第一作者、标题+venue+年份检索 Crossref、正式出版社页和正式会议 proceedings
4. 只接受能交叉匹配标题、作者、venue、年份的 DOI
5. DOI 指向勘误、社论、摘要、预印本或不同版本时拒绝自动接受
6. 把“暂未找到”“确认无公开 DOI”“候选 DOI 待人工核验”分成不同状态
7. 不把 arXiv 编号、Paper ID、URL 片段、BibTeX citation key 或年份当作 DOI
8. 2026 年记录允许 DOI 尚未分配，但必须保留正式会议/出版社页面和检索证据

## PDF 获取与验证

按以下优先级尝试：

1. 笔记中的正式 PDF URL
2. 正式出版社或会议 PDF
3. DOI 落地页解析出的 PDF
4. 合法开放获取地址
5. 已登录浏览器/Connector 中可访问的 IEEE、Nature 或 Science 页面

遵守以下硬规则：

- 不绕过付费墙、验证码、机构访问控制或版权限制
- IEEE 可利用本机现有登录状态；Nature、Science 和会议登录状态不得假定可用
- 下载前后记录 URL、HTTP 状态、Content-Type、文件大小和时间
- 文件必须以 `%PDF-` 开头，不能是 HTML 登录页、验证码页、摘要页、Snapshot 或补充材料
- 能从 PDF 文本或来源元数据确认题名/版本时才标记为已验证
- 下载失败不阻止创建正确的 Zotero 元数据父条目，但必须进入 `pdf_download_failed` 或人工待处理状态
- 不反复高速重试；遵守服务方限速，遇到 429/403/登录页立即退避或转浏览器流程
