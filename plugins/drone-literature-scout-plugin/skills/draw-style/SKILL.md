# Draw Style

## 插件级轻量故障协作

> [!important]- **快路径与慢路径**
> - **正常成功路径不写故障库**；普通成功步骤直接继续，不为每次工具调用扫描、查询或记录
> - 当前组件已知脆弱、准备复用历史方案或某路线刚失败时，才运行 `incident_registry.py preflight`：先查项目守卫指定的**本地事故库**，未命中再查**公共事故库只读**；都无匹配就继续
> - 出现**任意异常、非零退出、权限拒绝、结果缺失或验证失败**时，立即运行 `capture-event` 写入本地事故库；记录后才改变路线，同一路线再次执行前必须通过 retry guard
> - **最终回答前**扫描本任务的实际工具结果，补记尚未入库的真实失败、拒绝、非零退出和验证失败；预期 TDD RED、受控探针和用户取消不算产品事故
> - **只有本轮事件发生变化**或历史方案获得新的复用结果时才检查候选；候选非空才加载 `promotion_audit.py`，否则不增加额外工作
> - **本 Skill 的效果验证**：图中对象、数字、公式、几何、箭头、统计口径和阅读顺序均可核验；在目标宽度可读；原始质量与来源没有衰减
> - 插件任务开始或 Skill 清单变化时读取 `../../references/skill-collaboration-contract.md` 并动态核对职责；同一任务内清单未变时不重复枚举全部 Skill

## 1. 职责与调用合同

`draw-style` 是插件内唯一的通用科研绘图负责人，负责选择视觉路线、构建语义蓝图、生成或编辑图像、检查视觉与统计质量。它不决定某篇 Obsidian 笔记是否需要配图，也不接管调用方的保存、嵌入、引用或业务结论。

调用方只需交接：

- `usage_context`：PPT、Obsidian、正式论文方法图、正式论文数据图/表格之一
- `visual_claim`：读者看完必须理解的**单一视觉主张**
- `required_content`：必须出现的对象、数据、公式、标签、关系和必要对照
- `evidence`：本地论文页码/图号/公式、用户数据、权威来源或可核算事实
- `output_constraints`：语言、尺寸、嵌入宽度、格式、来源和禁止内容

输出包括一个经过验收的主候选，以及简短说明：路线、语义核验结果、逻辑闭环结果、质量门结果、来源和仍未从证据确认的边界。

### 单次执行主链与证据复用

一次任务沿同一主链推进，不在各子部分重新做一套相同核验：

1. 判定 `usage_context`，加载共同视觉语言和当前分支所需 reference；同一任务、同一版本下每个 reference 只完整读取一次。
2. 汇总调用方证据、原文/数据事实和不可推断边界，形成 `VISUAL_SOURCE_EVIDENCE`。
3. 依据该证据建立并预检唯一 `VISUAL_BLUEPRINT`；对象、数量、符号、关系、布局、逐字文本、输出约束和禁项都在其中锁定。
4. 按 A/B/C/D 路线生成或编辑一个主候选；多图时每个知识点各自拥有蓝图和候选。
5. 在目标使用宽度依次执行一次八项质量门，形成 `VISUAL_ACCEPTANCE`；通过后冻结，失败则按结构性或局部错误边界回到相应步骤。

同一门内只生成一次当前权威证据，后续步骤引用上述证据 ID，不重复读取、重复审计或另建平行台账。输入、原文/数据、调用上下文、目标尺寸、候选资产发生变化，或原规则明确要求进入新的证据边界时，必须刷新受影响证据；不得跨边界复用旧结论。

## 2. 四场景轻量路由

只**按需加载**对应场景文件与共同规则，不一次读取所有参考材料，也**不统一成一种风格**：

- **PPT 图**：加载 `references/ppt-figures.md`；知识点少、视觉中心强、远距离可读
- **Obsidian 知识点图**：加载 `references/obsidian-knowledge-figures.md`；一个知识点一个语义闭环，正常笔记宽度可读
- **正式论文方法/原理图**：加载 `references/paper-method-figures.md`；对象、符号、因果、状态更新和跨面板共享条件严格一致
- **正式论文数据图/表格**：先加载 `references/data-chart-selector.md`，再加载 `references/paper-data-figures.md`；数据、轴、单位、基线、样本量与不确定性定义可追溯

所有场景都加载 `references/visual-language.md`。“**用户确认的稳定个人配色**”的紧凑实现是：普通新图的颜色入口只有**六个核心色族、四条连续数据色阶、三套命名模板**；字体按数据坐标、正式方法图、中文、数学和少量手写短标签的角色表选择。**精确复现时才加载** `references/color-font-archive.md`，普通新图不从历史色号拼调色板。涉及空间、视角、多面板或局部放大时再加载 `references/layout-patterns.md`。RSS 图库和学习台账只作模式证据，不能压过当前任务的原文或数据。分析 RSS 语料时才按需加载 `references/rss2026-analysis-protocol.md` 与 `references/rss2026-learning-ledger.md`。

### 数据图选型门

真实数据图先走 `数据结构 → 候选图型 → 人工定型 → 生产软件`，不能先按习惯打开某个软件再套图表。若用户尚未指定图型，按 `data-chart-selector.md` 给出 2—4 个统计上成立的候选、优缺点与误读风险，由用户最终选择；已明确且成立时直接执行。WPS 能忠实表达时优先保留原生可编辑图；高级二维统计和复杂布局用 Python；真实 2.5D/3D 空间效果用 MATLAB；复合图允许逐面板路由，但全图视觉语言必须统一。

其他领域论文场景中，如 `visualizing-and-writing-modeling-papers` 可用，选图前读取其当前合同：该 skill 负责数据血缘、统计含义、人工选定方法和发布约束，`draw-style` 负责候选图型、视觉编码与终稿验收。普通论文、PPT 和 Obsidian 图不受其他领域专属入口门限制。

### 母版选择

先从 `visual-language.md` 的 M1—M9 中选择**一个主母版**。复杂异构模块、双向反馈、训练—策略协同或神经—符号闭环出现时，先做**模板级优先判断**：判断能否采用 **M9 非对称模块星座**；它是全库最高优先级母版之一。M9 不适用时再按读者任务选择其他母版。只有一个必要的次级问题无法由主母版回答时，才增加**最多一个辅助母版**；颜色、箭头、标记和阴影只是叠加语法，不单独决定母版。不直接模仿某一张 RSS 图的全部外观，逐图卡只用于追溯证据。

正式论文流程图需要明确立体层次时，默认使用可控的**两层外部右下阴影**：近距离低模糊的**接触阴影**分离卡片边缘，稍远且更柔的**扩散阴影**建立空间层次。二者必须低透明、同方向、全图一致，禁止发光、重黑边和漂浮感。

## 3. 证据优先与语义蓝图

### 3.1 先锁定事实

1. 优先读取调用方给出的本地原文、Zotero PDF、数据或权威原图；论文知识点必须**先读取本地原文依据**，**论文怎样定义就怎样画**。
2. 区分截图可见事实、caption 明示事实、可计算事实与未确认内容。未确认内容不让模型自由补全。
3. 先写可核验的**语义蓝图**，再写最终提示词；蓝图必须包含知识点与单一视觉主张、布局骨架与阅读顺序、对象清单及位置关系、过程编码、精确夹具、语义配色、字体、间距与原生输出要求、明确禁项。
4. 先选择表达维度：按对象与论证需要选择 **2D、2.5D、3D**，而不是按审美偏好选择。

### 3.2 语义蓝图最小结构

```text
视觉主张：
读者任务：
证据与不可推断边界：
逻辑闭环五段链：对象是什么 → 输入从哪里来 → 箭头/变换做什么 → 输出怎样得到 → 结论的边界是什么
画布与阅读顺序：
对象、数量、位置、状态：
关系、箭头、路径、更新、终止：
术语、缩写、符号与解释责任方：
箭头、线型、颜色、编号的逐项语义：
数字、样本、阈值与中间状态的来源：
读图与图例需补足的内容：
必须逐字出现的文字/公式/数字：
颜色与线型的语义：
2D / 2.5D / 3D 及理由：
禁止遗漏、禁止新增、禁止误画：
目标尺寸、格式和验收宽度：
```

每个非显然术语、缩写、符号、数字、箭头、线型和颜色身份必须有且只有一个主要**解释责任方**：图内直接形象化并短标，或由紧邻图后的 caption/“读图与图例”解释。二者必须互补且合起来完整，不能同时省略，也不能依赖正文远处补洞。语义完整与解释准确是前置硬门槛；正常宽度可读、紧凑、美观和格式偏好均在其后。

**简洁是保留逻辑闭环后的最小表达**，不是追求最少文字、最少对象或最少图例条目。删除后若出现名称悬空、箭头无动作、数字无来源、输入输出断链或边界消失，即判结构性失败。

## 4. 生产路线：A → B → 必要时 D，C 为例外

同等效果和质量下选择依赖更少、生成更快、维护更简单的路线。合格现图直接保留；常规新图只走 A → B → 必要时 D。

- **A. 权威原图**：论文或可靠来源已有完全匹配、清晰、可追溯的图时使用；保留来源、访问日期和裁切说明，不裁整页或长图注
- **B. Image2（默认）**：算法、控制、机制、环境表示、空间关系、方法比较和概念性几何默认用 Image2；公式、数学符号、坐标轴、栅格或算法内容本身都不能触发代码路线
- **C. 确定性数据生产（数据图专用）**：真实数据统计图按选择器使用 WPS、Python、MATLAB 或逐面板混合路线；必须逐坐标、逐尺度、逐数值复现。数据图不使用 Image2 生成数值、误差或曲线；它只服务真实数据，不是与 Image2 平级的日常备选
- **D. 最小局部修正**：整体结构与语义已通过、只剩单一局部小错误时使用；优先局部生成式编辑，只有极短文字/数字/公式需要绝对精确且编辑不稳时才允许风格一致的最小覆盖

结构、层级、比例、路径、拓扑、多处文字/数字/公式错误均为**结构性失败**：必须重写语义蓝图与提示词并整图重生成，禁止在外围缝补表格、公式卡或说明框。

## 5. Image2 一次成图与轻量并发

- 先做**提示词预检**：把证据事实、对象数量、位置、共享条件、关键数字、逐字文本、箭头、解释责任方、图例补充项和禁项写全，再生成**一个主候选**；**不为比较而生成多个变体**
- 公开质量档位时必须选择最高档；未公开质量档位时用工具可用的**最高原生分辨率**并不得虚报。保存工具直接返回的原始 PNG，**不重新压缩**、不转有损格式、不插值放大
- 多图任务采用每个知识点一个独立 Image2 请求，按当前可用安全并发槽同批发出；不把无关知识点塞进同一画布
- 每张独立验收：合格图立即冻结；只把失败图在修改蓝图/提示词后送入下一波并发
- 纯审美轻微偏差在八项门槛已通过时直接接受；禁止对已语义合格候选做大面积覆盖
- 提速不得降低质量档位、原生分辨率、提示词完整性或验收强度

## 6. 八项硬质量门槛（逻辑闭环 + 原七项硬质量门槛）

依次验收，后一项不能补救前一项：

1. **逻辑闭环与术语落地**：图与其紧邻图例合起来能回答五段链；所有术语、缩写、符号、数字、箭头、线型和颜色身份都有解释责任方
2. **内容完整**：视觉主张所需对象、过程、对照、结果和边界齐全
3. **语义准确**：对象类别、数量、状态、因果、拓扑、视角与原证据一致
4. **数学与文字准确**：公式、数字、单位、上下标、图号、方向逐字符核对
5. **正常宽度可读**：标题、标签、公式、箭头不重叠、不截断、不被连线穿过
6. **紧凑但不拥挤**：信息密度均匀、面板间距一致、无意义空白被裁掉
7. **风格与颜色有意义**：颜色、线型、形状编码稳定，审美服务于区分和阅读
8. **来源与笔记集成正确**：来源、保存格式、嵌入路径、caption/图例职责和最终资产一致

验收第一项时先做**孤儿元素审计**：枚举图内所有非显然文本、符号、数字、箭头、线型、颜色身份和样本编号，逐项核对解释责任方；再做**读者复述测试**：不借助原论文正文，读者能说清对象是什么、箭头做什么、结果从哪里来、边界是什么。旧图替换还必须满足零质量衰减：新图全部通过八项门槛，关键维度均不弱于旧图；条件允许时原生宽度约为计划嵌入宽度的 2 倍。任何一项失败都不交付。

## 7. RSS 确认与冻结边界

RSS 审阅可使用 10 图窗口提速，但底层仍按每 5 张保存和验收。**整批冻结**只由该批完整分析获得用户明确确认后触发；用户对某一视觉知识的**单条规则确认**，只允许把该条规则按其适用条件写入稳定参考，不把所在批次的其他内容自动改为已确认，也不替代批次 `freeze-batch`。

只加载当前场景所需文件。新语料先写入批次分析与适用条件，用户确认后才融合成稳定规则；相互冲突但场景不同的好风格并列保留。
