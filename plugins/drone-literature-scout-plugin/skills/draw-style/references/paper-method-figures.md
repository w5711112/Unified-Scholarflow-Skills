# 正式论文方法/原理图模式

## 1. 论文级证据与职责

每个对象、公式、符号、箭头和面板关系都必须来自方法定义、算法、实验设置或可核算事实。不能凭常见做法补出论文没有定义的模块。

## 2. 方法图语义合同

逐项核对：

- 输入、输出、训练/推理阶段和信息可用性；
- 对象、状态、模块、缓存、损失、控制量和物理落点；
- 因果、数据流、梯度流、反馈回路与停止梯度；
- 状态更新前后、写回位置、循环与终止；
- 跨面板共享的输入、尺度、符号、颜色和唯一变化因素。

虚线框只能表达定义明确的阶段、模块组或可用性边界；火焰、雪花、锁等符号必须有清楚图例，不能只靠颜色猜含义。

## 3. 结构选择

- 多阶段方法以大区块建立全局顺序，局部模块只在需要复现或理解创新点处展开。
- 方法总图追求**完整但不过载**。当创新点跨越物理输入、几何关系、方程和优化时，可采用 `并行输入 → 主视觉场景 → 必要公式 → 紧凑关系图 → 输出`：输入各用一个代表性对象，主场景占最大面积，公式只保留决定未知量的部分，关系图只保留必要状态/因子。不要为了“完整”展开普通网络层、全部推导或完整后端。
- 系统/设备图可以用 2.5D 或 3D 建立物理流，再以管线颜色、箭头和 inset 解释传质、反应或控制。
- 对照面板保持相同视角、尺度和对象位置；差异元素单独高亮。
- 真实图像、照片与矢量示意混用时，统一边框、裁切比例、标签锚点和颜色语义。
- 工程系统图可采用 `外部 I/O → 内部节点 → 框内子语义` 的容器层级：外部流与内部计算分区，节点内直接绑定 topic、消息或输出，频率贴在对应边旁；颜色只区分类别，端口和箭头负责精确依赖。
- 机械/运动学创新点至少画出一个可核验实例，按需标明基座、端点、约束域、目标运动与修正方向；关键碰撞量用局部放大窗，不用单个 `Optimization` 方框代替原理。
- 外部引导器、评分器或可行性模型采用 `训练定义 → 推理插入 → 分布转向 → 现实结果`：先说明它怎样学，再标出它介入基础策略的精确步骤，随后展示变量分布怎样变化，最后落到成功/失败或物理行为。不能只画一个漂浮模块。
- 概率与评分语义不同：可并置 **2D 动作分布与 3D 可行性评分面**，用同一批样本点或清楚引线建立对应；3D 面没有轴与单位时只能作机制示意，不能承担定量结论。

### 3.1 M2 跨表示身份合同

同一方法跨场景、依赖图、局部策略卡、公式和最终行为时，必须复用编号、符号、对象位置、状态名与共享条件。不同区域可使用不同视觉介质，但每次转换都要让读者知道“哪个对象变成了哪个表示”；跨表示对应用点线或编号，不冒充因果箭头。

### 3.2 M3 箭头职责与系统边界

- **M3 箭头职责**：阶段主链用粗直箭头，节点依赖用细线，物理轨迹用弯曲路径，反馈或跨表示对应用虚线；四类关系不能只靠一种箭头表达。
- 容器边界、虚线圆角和长连接采用**共享曲率语言**，长线沿留白或外缘布置，不穿公式、标签和节点。
- 多路输入在真实融合前保持分离，汇合点、前向计算、反馈回路、终止条件和物理输出分别可追踪。
- 自然语言指令是正式输入时，可使用带引号的**任务指令卡**替代普通矩形：纸张轮廓、轻微不齐底边和克制的外部右下阴影负责“这是原始命令”的物件感，卡内只保留完整的一句任务文本；字体可选 Comic Sans MS/Comic Neue 类圆润手写体，但不得用于长 caption 或关键数学式。
- RSS2026_035 的反例边界：无语义杂色、同级形状混乱、**孤立重阴影**以及照片/矢量对象边框不一致，均不能用模块数量或完整流程为其辩护。

### 3.3 M9 非对称模块星座

RSS2026_060 是全部参考图中位于前列的**模板级基准**，不是普通风格样例。正式论文方法图包含异构模块、双向反馈、训练—策略协同或神经—符号闭环时，母版选择阶段必须**先判断是否适用 M9**；适用时，不再默认退化为等宽等高的普通框图。

流程清楚不等于把所有模块做成等宽等高的卡片矩阵。创新链由不同对象类型组成时，优先追求**不规则但流程清晰**的模块星座：先固定一条可复述的主链和一个视觉锚点，再让卫星模块按职责围绕它形成**非对称平衡**。

- 使用**大框、小框、层叠卡与梯形**建立语义层级：大圆角容器表示系统或策略域，小框表示单一运算，层叠卡表示数据集/序列/多个样本，梯形表示编码、聚类或映射。形状丰富必须来自对象类型，不能随机换形状装饰。
- 允许上下错位和尺度差形成节奏，但每个连接仍应沿明确的前向、反馈或监督路径；分区边界附近保留通道，避免箭头穿字。短缩写优先放在框内，解释性长句移到 caption。
- 当读者必须先看问题—方案对比、再看内部机制时，采用**有边界的非对称填充**：外层保持一个完整圆角域，内部允许一张比较卡压住左上、右上保留主方案、下部横跨两个互补机制。另一种实施是主流程占左侧 70%—80%，模型细节作为右侧窄栏；两种都要求**完整外框内错落**，用共享边界收束不同尺度，而不是把所有模块重新等分。
- **完整外框内错落**不等于把每个空隙填满：先留出连续箭头通道和标签安全区，再让照片、状态卡、层叠编码器、子模型细节占据剩余的大块空间。目标是消除无意义留白，同时保留能解释主链的负空间。
- 色彩按区域职责分布，而不是轮流上色：例如浅黄承担数据与中间产物，浅绿承担可复用结构/动作，浅红承担学习或策略更新，浅灰承担容器和阶段分界；同一角色配更深边界或箭头形成局部层次。
- 以最大语义容器或主策略模块作为**视觉锚点**，采用统一的**两层外部右下阴影**建立可见深度。接触阴影短而略实，扩散阴影更远、更柔、更淡，普通卫星模块按层级减弱。禁止发光、孤立重影、重黑边和每个框强度相同的机械悬浮。
- RSS2026_060 的竖直分界在整张 1272 px 画布上位于约 492 px，左右约为 **38.68% / 61.32%**；但若只计算非白内容包围盒，其位置约为 **29.66% / 70.34%**。因此**黄金分割只作构图候选**：可用 38:62 作为首轮布局起点，但最终必须由内容权重、阅读路径和留白质量验证，不能倒推作者严格采用了黄金分割。
- RSS2026_067 提供“上部问题—方案、下部双机制”的紧凑证据；RSS2026_068 提供“完整主流程＋右侧模型细节栏”的高密度证据。两者只补强 M9 的有边界布局合同，模板级优先级仍由 RSS2026_060 的非对称模块星座承担。
- **蓝紫双专家架构**是 M9/T1 的高优先级实施变体，而不是新的母版：一个最大浅蓝主模块承担共享主干，深蓝与深紫分别绑定两个语义专家，右侧细节栏复用同色双支路并在共享层汇合；左侧异构输入和下方任务卡采用不等面积圆角容器。RSS2026_103 的价值在于“共享主干＋双专家＋任务卫星”的职责与颜色一一对应，不是因为蓝紫本身高级。
- 反例是“伪不规则”：主链不明、每个框任意尺寸、颜色与形状没有职责、空白碎裂或多个锚点争夺注意力。真正的不规则美仍有一套可追踪的对齐线、曲率、色彩角色和箭头语法。

### 3.4 极简关系图与资源映射

- **极简对象几何＋变量夹具**适合动力学、运动学、接触与约束定义：先画可识别的物理对象和关节/接触点，再把质量、长度、角度、控制量、法向或坐标直接锚定到对象。尺寸双箭头、角度弧线、力箭头和运动方向不能混用；黑白线稿与数学斜体已经足够时不增加色块和阴影。
- **极简线条知识点图的信息上限**：一幅图优先只承载一个主对象、一个主关系，以及 2—3 组紧贴对象的变量夹具；允许增加一个正交/局部小视图，但它必须核验同一关系。若像 RSS2026_092 那样同时出现主轨迹板、相机侧视、圆形视场和多组坐标，已到单图上限；继续增加概念时应拆图或以极浅分区建立层级。极简不等于纯黑白：在 RSS2026_091 一类共享流形对照中，可只给主动修正箭头一个强调色，其余对象保持中性。
- **物理边界短排线**适合墙面、遮挡面、触碰面和剖切边：沿边界内侧布置同角度、等长度、等间距的粗短斜线，配合统一圆头/方头线帽，使读者不靠大色块也能识别“这是实体墙”。RSS2026_096 证明短排线、简笔相机和少量光线色足以构成高级的光学原理图；每个面板只让当前光学现象着色。
- 同一几何对象需要逐步解释拓扑、查询、距离和区域时，复用对象比例、位置和背景，只在各面板增加一个语义层；不要每步重画不同视角。该合同的布局细节见 `layout-patterns.md` 的“共享几何逐层揭示”。
- **资源层级—并行计算映射**适合线程、内存、寄存器、缓存和并行宽度：使用共享行高或泳道对齐资源层级，左右宽度直接表现串行/并行组织差异，粗箭头表示搬运或溢出，回路表示更新。颜色绑定资源类别，不按每个线程轮流换色；数值宽度与并行度只有在正式定义时才按比例。
- 并行度或批处理结构可以由**重复对象编码**：相同小块、层叠卡、平行箭头或数组列分别对应 scenario、thread、trajectory、candidate 等真实维度。重复数量可以示意“多”，但若要表达精确数量必须逐项可核；不能用一排装饰方块冒充 SIMD 或 batch 证据。
- 紧凑分区证据板可以让照片、公式和计算阶段同处一图，但必须先给出一条主链和少量代表性证据。面板角标用于引用和定位，不替代阶段标题；公式只保留决定流程的关键式。

### 3.5 伪代码、紧凑主图与阶段闭环

- **伪代码算法卡**适合把迭代算法作为可直接引用的视觉对象：使用单个中等圆角外框、深色标题栏、近白浅灰正文和清楚的内缩层级。标题栏用白字深底建立入口；正文以步骤编号和缩进表达控制结构，粗体只标循环条件、动作动词或阶段名，不把整段全部加粗。边框在终稿尺寸必须仍清楚，不能细到接近表格网格；算法变量继续使用正式数学字体。RSS2026_081 的正文平坦显示色为 `#F2F2F2`，标题栏/外框为 `#3F3F3F`；截图中彩色文献编号框属于阅读器/批注叠层，不进入算法卡风格。
- 高密度论文主图可使用**语义分区的低对比渐变底**：渐变只铺在大的子系统容器上，用冷暖或明度缓慢变化区分物理职责；内部节点仍用平坦浅色和稳定描边。RSS2026_085 的冷区从近白蓝 `#F4F8FB` 过渡到 `#D0E2F1`，暖区从近白粉 `#FEF4F2` 过渡到 `#F9DAC5`。渐变必须绑定“瞬时/补偿”等正式子系统差异，不能给每个模块各加一层渐变。
- 紧凑主图按“模型内部 → 在线时序 → 闭环部署”或等价的三层证据组织：最大面板解释创新机制，次面板解释执行时序，最小面板解释物理落点。内容填满来自职责互补和尺度分级，不是把所有空隙塞入文字；统一圆角、边距、标题基线和箭头端点负责收束密度。
- **阶段闭环证据卡**用于 broad/narrow phase、采样/规划/优化等多阶段算法：每个大阶段内部都形成 `输入表示 → 核心操作/几何 → 输出或判定` 的小闭环，阶段之间只保留一个命名清楚的 handoff。这样内容丰富仍可追踪；若一个大框只有标题和公式、没有可见操作或输出，它不是完整证据卡。
- 圆润手写感字体可以用于这类方法图的短标题、SIMD/belief/scenario 等短标签和少量箭头说明，并与层叠卡、圆角容器共同降低生硬感；数学式、坐标、长说明和 caption 仍使用正式数学/正文家族。

### 3.6 复杂框架的反例边界

- 重复照片条、虚线彩框、对话气泡、机器人图标和多种渲染素材同时出现时，先删去不承担独立证据的素材。内容数量不能弥补主链不清。
- **渐变粗箭头**通常会把方向、阶段身份和装饰混成一层；正式方法图优先使用单色、职责固定、端点清楚的箭头。只有连续量沿箭头真实变化且配有尺度时才允许渐变。
- 大面积空洞、跨越多区的长括号箭头、图标风格混杂和高差异同级色块会打散视觉锚点。先重建层级、对齐线和箭头通道，再讨论配色。
- **高饱和色相轮换**会让每个阶段都争抢注意力。若紫、红、橙、绿、蓝同时承担同级模块身份，先合并为 2—4 个语义色族，再用线型、形状和标签补充；彩色 caption 不能替代图内稳定编码。
- **公式占位不等于视觉解释**：左侧放公式、右侧放一张无证据关系的彩色曲面，不能自动形成方法总图。公式必须落到被计算的对象、采样过程、几何约束或输出；否则保留公式在正文，把图面还给真正的视觉机制。
- **操作性视觉落点**：浅色分区和完整箭头链只能建立框架，不能替代示意。每个主要阶段至少要有一个传感器、对象几何、动作、状态变化或物理结果作为箭头落点；若箭头大多只指向公式字母、损失符号和文本框，如 RSS2026_098，则即使流程完整也仍不够形象。
- **蓝橙双主色竞争**不是“蓝色与橙色天然不搭”，而是两者在同一局部都以相近饱和度争当主角、面积/线宽又与语义重要性不匹配。RSS2026_094 中大面积浅蓝候选形状、饱和橙目标路径，再叠加红绿锚点，形成四个活跃色族；重绘应把上下文蓝降为更浅中性蓝，只保留橙色动作主轴，或用蓝/橙分别绑定两个真正同级对象并以中性结构桥接。

## 4. 排版与可复现性

正文可解释方法动机，图必须独立给出主流程和创新点。公式只保留决定结构或更新的关键式；长推导进正文。Caption 要自包含地说明面板、颜色/符号、训练与部署差异及关键限制。
