### 1. 截图身份

- 原文件：屏幕截图 2026-08-02 014642.png。
- 定位信息：`Fig. 2: Overview of Vec-QMDP.`。
- 图的范式类别：场景采样—向量化规划—向量化轨迹优化的三域高密度框架图。
- **用户个人学习重点**：学习 `Vectorized QMDP Planning` 等整图字体、紧凑无空洞的规整形式，以及左下蓝色/紫色层叠效果；配色本身有待加强。
- **补充核读**：标题与短标签外观延续 Comic Sans MS/Comic Neue 类圆润手写感；真正组织密度的是 repeated scenario blocks、stacked layers、parallel arrows 和 block-diagonal 区域，而不只是字体。

### 2. 图本身表达什么

先把 belief 采样成 M×N scenarios 并按 SoA 批处理，再在 CPU 多线程和 SIMD 的全局/局部向量化下执行 QMDP 搜索，得到动作序列；随后生成候选轨迹并用 block-diagonal cross-scenario evaluation 选择最优轨迹。

### 3. 逐元素与连接核读

**逐元素账本：**

- `(a)` 顶部圆角域以波形 `belief` 为中心，左右分别展示 sample/re-sample、scenario batching、CPU cores 及 AoS→SoA 数据重排。
- `(b)` 左下大域顶部是多个 scenario tree/线程卡，下方分 `global vectorization` 与 `local vectorization`：左侧层叠 transition dynamics，右侧树结构与栅格车辆局部问题；蓝色多层边缘表示并行实例。
- `(c)` 右下大域为大矩阵/块对角区域，绿色小块沿顶部和左侧表示 worlds/trajectories；粗蓝对角箭头标 multi-threading，内部 inset 用矩阵示意 trajectory×world 组合和 SIMD。
- 三个大域都用浅灰圆角外框，标题置于顶部胶囊条；薄荷绿重复块、蓝色层叠、紫色层叠承担批处理/并行身份。

**箭头/连线账本：**

- belief → 左右 scenario batches｜浅绿块箭头｜sample/re-sample｜采样与重采样。
- `(a)` → `(b)/(c)`｜浅绿向下箭头｜无额外边标签｜场景批进入两类向量化计算。
- `(b)` → `(c)`｜灰色粗直箭头｜optimal action sequence｜规划输出进入轨迹优化。
- `(b)` 内部蓝色弯箭头与紫色箭头｜multi-threading/SIMD｜分别表示线程和向量化方向。
- `(c)` → 底部｜灰色向下箭头｜optimal trajectory τ*｜最终选择。

**关系账本：**

- 重复小块编码 scenario/CPU core/world，层叠卡编码并行实例，矩阵编码跨场景批评估；相同“多重对象”语法跨域复用。
- 手写感文字负责阶段标题和短说明，数学变量保持正式斜体。

### 4. 全局构图与阅读路径

顶部一条横向采样域，下部左右两个近等高大域形成倒 T 结构。大箭头只连接三个阶段；细箭头留在域内。主体几乎铺满外框，但阶段边界和标题条提供稳定停顿，空白主要作为箭头通道。

### 5. 局部视觉语法

薄荷绿表示 scenario/batch，浅蓝和深蓝表示并行规划结构，紫色表示 SIMD/layer stack，灰色表示容器和 block diagonal 背景。重复块、堆叠边和并行箭头比文字更直接地传达 vectorized。

### 6. 为什么有效

三个标题回答全局阶段，阶段内部又用不同视觉介质回答采样、树搜索和矩阵评估。重复对象的方向和尺度保持一致，读者能从“一个→一批→矩阵”感知并行化。大容器尺寸与信息量匹配，避免了普通等宽小框流程。

### 7. 可以吸收的绘图知识

- 强化“重复对象编码并行度”：块阵列、层叠卡、平行箭头和矩阵必须分别绑定真实 batch/thread/trajectory 维度。
- 圆润手写感用于阶段标题和短标签可减轻工程图僵硬感；长说明和数学式不跟随。
- 三域排版可作为 M3/M9 的规整变体：外框统一，内部表达不强行同构。

### 8. 不足、误读风险与不应照搬

整体配色偏淡，部分浅绿块和浅灰箭头对比不足；大量斜排 `SIMD/multi-threading` 文字缩小时较难读。层叠数量不是精确线程数，不得从图形数量反推并行规模。

### 9. 本图最值得学习什么（收录理由）

学习用重复、层叠和矩阵三种结构语法把“向量化/并行化”画出来，并在高密度下仍维持三阶段主路径。

### 10. 证据边界

每个小块与具体 scenario/thread 的精确映射、CPU 数量、SIMD 宽度、标题源字体和软件未从截图完全确认。

- 图的范式类别：上下两阶段、各自具备输入—操作—输出的碰撞检测证据卡。
- **用户个人学习重点**：内容丰富，可能来自字体和圆弧框；需要分析为什么仍显得清楚。
- **补充核读**：核心原因是 broad/narrow 两个大阶段都有内部闭环，且只通过一条 `Candidates' Data in SoA` 命名 handoff 相连；圆角和字体只是统一外观。

### 2. 图本身表达什么

Broad phase 通过向量化 AABB 查询和 pointer-less indexing 从大量节点中筛出潜在碰撞候选；Narrow phase 把候选位置/姿态按 SoA 输入并行 SAT separating-axis 检查，输出安全或碰撞判定。

### 3. 逐元素与连接核读

**逐元素账本：**

- `(a)` 上部大圆角框：左上红色车辆为 query；中上灰色数组为 pointer-less indexing；左下灰色栅格/重叠矩形表示空间索引；中央小框展示 Frenet 坐标中的 vectorized AABB test；底部数组用黄色格标出 potentially colliding nodes。
- `(b)` 下部大圆角框：左侧三排黄色 SoA 数组分别为 `x_i/y_i/θ_i`；中间多个紫色层叠平面表示并行 SAT/Separating Axis 检查；右侧圆形判定节点向上绿色盾牌、向下红色碰撞车输出。
- 两阶段标题、SIMD Gather、Pointer-less Indexing 等短标签使用圆润手写感；数学数组变量保持衬线斜体。

**箭头/连线账本：**

- 红车/栅格 → 索引数组｜灰色箭头｜Query/Vectorized｜构造 broad-phase 查询。
- 索引数组 → AABB test → candidate array｜灰色箭头｜Pointer-less Indexing/Potentially Colliding Nodes｜筛选候选。
- `(a)` → `(b)`｜中央单一下箭头｜Candidates' Data in SoA｜阶段交接。
- SoA arrays → stacked SAT → decision node｜白/黑箭头｜SIMD/Separating Axis｜精细碰撞判定。

**关系账本：**

- 上阶段内部是查询表示→索引→筛选；下阶段内部是数据布局→几何测试→二值输出。
- 黄色在上层只标候选节点、下层只标候选输入；紫色固定并行 SAT 层，绿色/红色固定安全/碰撞结果。

### 4. 全局构图与阅读路径

上下两个完整圆角容器共享宽度，中间只留一个短交接箭头。每个容器内遵循左输入、中操作、右/下输出；内容密集但方向一致。外框圆角、标题基线和内边距统一，建立规整骨架。

### 5. 局部视觉语法

灰色数组和网格承担数据结构，黄色只突出筛出的候选，紫色层叠表现并行核验，红/绿图标给最终二元判定。车辆素材虽是位图/渲染，但跨面板保持同一身份。

### 6. 为什么有效

“丰富”来自每阶段都给出三类互补证据，而非堆很多同级框。命名 handoff 消除了上下阶段之间的歧义；圆角框把复杂局部限定在清楚边界内。重复数组、层叠平面和输出图标分别回答数据、计算与结果。

### 7. 可以吸收的绘图知识

- 固化“阶段闭环证据卡”：每阶段至少可见输入表示、核心操作/几何和输出/判定。
- 阶段间只保留一个正式命名的数据 handoff，避免多条跨区线。
- 圆角外框、标题字形和内边距统一；内部对象允许异构，但颜色必须按职责复用。

### 8. 不足、误读风险与不应照搬

部分汽车素材角度与二维示意风格不完全一致；手写标签较多，缩小时可能显得随意。绿色/红色判定图标较像演示文稿素材，正式重绘可改成更统一的矢量符号。

### 9. 本图最值得学习什么（收录理由）

它证明内容丰富仍能清楚的关键是“阶段内闭环＋阶段间单 handoff”，而不是单纯圆角、字体或更多颜色。

### 10. 证据边界

### 1. 截图身份

- 原文件：屏幕截图 2026-08-02 015020.png。
- 定位信息：`Fig. 3: Coverage maps for two candidate sensing locations ...`。
- 图的范式类别：双面板二维 covariance 场＋候选位置＋阈值覆盖边界。
- **用户个人学习重点**：了解这种热力/覆盖图何时合适，以及右侧“温度表”式色条的职责。
- **补充核读**：底层是连续 covariance pseudocolor/heatmap；红叉是 candidate sensing location；白色虚线是达到 posterior-variance threshold 的 evaluation locations 边界。三者不是同一种数据。

### 2. 图本身表达什么

非平稳核下，不同候选感知位置对空间各处 covariance 的影响范围不同。白色虚线圈出该候选能够保证目标后验方差阈值的覆盖集合。

### 3. 逐元素与连接核读

**逐元素账本：**

- 左右两面板共享 X/Y 坐标，范围约 `[-17,17]`；深蓝背景表示低 covariance，紫—橙—黄区域表示更高值。
- 左候选红叉位于约 `(-14,2)`，形成小而局部的暖色峰；右候选约 `(12,-10)`，形成更大的非对称暖色域。
- 白色粗虚线分别围住候选可覆盖的 evaluation locations；左为小闭合 blob，右边界延伸到绘图区右/下边缘。
- 最右单一竖直色条标 `Covariance`，刻度约 0.2—1.0；两面板共享同一色条。

**箭头/连线账本：**

- 本图没有方向箭头。虚线是等阈值集合边界，不表示路径；红叉是位置标记，不表示失败。

**关系账本：**

- 二维位置承载空间坐标，颜色承载连续 covariance，红叉承载候选位置，白线承载阈值判定。
- 两面板改变候选位置，其余轴域、色条和视觉编码保持一致。

### 4. 全局构图与阅读路径

两幅等大的方形坐标图并排，共享右侧窄色条。图例放在左图上方深色低值区，避免遮住主要暖色峰；面板之间保留足够间距容纳 y 标签。

### 5. 局部视觉语法

连续色面提供全局强度，白色虚线在深蓝和暖色上都保持高可见度，红叉以形状和颜色双重强调候选。色条给出连续量名和数值方向。

### 6. 为什么有效

读者不仅看到“哪里 covariance 高”，还能直接判断“哪些区域满足阈值”；共享色条使两个候选的场强可比较。阈值边界将连续场转成可操作覆盖集合，但没有丢失底层梯度。

### 7. 可以吸收的绘图知识

- 新增“覆盖场＋阈值边界”：heatmap/pseudocolor＋candidate marker＋threshold contour＋shared colorbar。
- 适用于 sensing coverage、posterior variance、risk reachability、visibility、通信覆盖和安全概率等空间问题。
- Python 用 `pcolormesh/imshow + contour + scatter + colorbar`；MATLAB 用 `imagesc/pcolor + contour + plot + colorbar`。比较面板共享 `vmin/vmax`、axis limits 和 aspect。

### 8. 不足、误读风险与不应照搬

截图未标出虚线对应的具体阈值数值，必须由 caption/图例补足；色条下界似乎没有从 0 标起，需说明规范化范围。白虚线较粗，复杂边界时可能遮住局部场值。不要把覆盖边界称为置信区间。

### 9. 本图最值得学习什么（收录理由）

学习用连续场、候选点和阈值轮廓三层证据同时表达“强度在哪里”和“可保证区域在哪里”，并用共享色条支持候选间公平比较。

### 10. 证据边界

covariance 的定义、核参数、网格分辨率、插值方式、阈值数值和色图源名称未从截图完全确认。

**箭头/连线账本：**

- 左公式列 → 中采样列 → 右隐式场｜黑色直箭头｜无边标签｜表示方法阶段顺序。

**关系账本：**

### 4. 全局构图与阅读路径

三列从左到右，宽度相近；左列文字/公式稀疏，中列路径占中部，右列大色块成为最强视觉中心。信息密度和视觉权重不匹配，读者容易先看右侧颜色而非任务定义。

### 5. 局部视觉语法

左/中主要黑白，右侧使用饱和绿黄红连续渐变；白点和虚线路径跨中右两列复用。标题为普通无衬线，数学用衬线斜体。

### 6. 为什么表现一般

公式没有落到一个可见任务对象，读者仍需阅读 caption 才知道 `p/q` 对应什么。右侧连续场没有色条或零集合说明，视觉强度大于证据强度；三列虽有箭头，但转换关系没有具体中间变量锚定。

### 7. 可以吸收的绘图知识

- 只保留“同一流形从采样路径到隐式表示”的跨表示复用。
- 重绘时左列加入一个最小任务对象实例，把 `p=f(q)` 锚到末端/轨迹/表面；右列加有量名的色条、零等值线和正负/高低说明。
- 公式应只保留决定视觉机制的一条，其余移到正文。

### 8. 不足、误读风险与不应照搬

公式占位不等于视觉解释；无色条彩色场不能承担定量语义；绿黄红色面可能暗示风险等级，却未被定义。不要为了“三阶段”而让三列等宽，也不要用大色块补左列缺失的图形证据。

### 9. 本图最值得学习什么（收录理由）

主要作为反例强化：方法总图必须把公式映射到对象和可见操作，连续场必须带正式色条；否则流程箭头只能连接三个标题，不能解释机制。

### 10. 证据边界

隐式函数的数值范围、零水平颜色、GP 核、采样顺序、流形维度与公式变量的具体物理任务未从截图完全确认。
