## RSS2026_101
<!-- rss2026-meta {"visible_figure_label":"Fig. 2","figure_track":"data/table","domain_tags":["Q-Function","Safe Set","Zero-level Boundary","Gradient Field"]} -->

### 1. 截图身份

- 原文件：屏幕截图 2026-08-02 021131.png。
- 定位信息：`Fig. 2: Q-Function Landscape.`。
- 图的范式类别：三投影视角的 bounded field、安全集边界、梯度箭头与专家点。
- **用户个人学习重点**：绿色区域内黄色五角星的配色可以学习；整体没有太多高级感，字体偏小。
- **补充核读**：它不是普通热力图，而是连续 Q 场＋绿色安全集＋红色零水平边界＋白色局部梯度箭头＋专家状态星形的多层空间诊断。

### 2. 图本身表达什么

从 front/side/top 三个二维投影视角展示 bounded Q-function 的值域、安全集合 `Q≥0`、边界附近梯度方向与 expert 状态位置。

### 3. 逐元素与连接核读

**逐元素账本：**

- 紫色背景场表示较低/非安全值，绿色闭合区域表示安全集合。
- 红色细边界对应 `Q=0` 等值线；白色短箭头沿边界周围指向局部改善方向。
- 黄色五角星标 expert/目标状态，黑/深描边帮助它从绿色区域中分离。
- 右侧单一色条给 bounded value；三个面板理论上共享同一规范化。

**箭头/连线账本：**

- 白箭头表示由 Q 场导出的局部梯度/策略方向，不是装饰性 inward arrows。
- 面板之间没有因果箭头，只是不同投影视角。

**关系账本：**

- 二维位置、连续颜色、零等值线、向量方向和离散 star 各自编码不同变量。

### 4. 全局构图与阅读路径

三个等大方形面板并排，右侧共享色条。读者先定位绿色安全集和黄色 expert，再比较边界形状与箭头方向。

### 5. 局部视觉语法

绿—紫大色块对比明显，红边与白箭头提供结构，黄色星作为小面积附件。字体和色条标签偏小，默认色图感较强。

### 6. 为什么有用但不够高级

证据层完整且职责分离，但配色、边界线宽、箭头密度和字号未经过终稿优化；多个强对比色同时出现，视觉略硬。

### 7. 可以吸收的绘图知识

- 新增“安全集场＋零水平边界＋梯度箭头”。
- 多视图共享轴域、归一化和色条；箭头由真实导数计算并稀疏采样。
- 黄色星只用于专家/目标等少量关键点，并给形状/文字冗余。

### 8. 不足、误读风险与不应照搬

没有场定义不能把绿色自动称安全；箭头若人工朝内绘制会伪造梯度。三投影不能替代完整高维几何，字体与色条须放大。

### 9. 本图最值得学习什么（收录理由）

把场值、可行集合、边界、局部方向和专家状态叠成互不冲突的五层证据。

### 10. 证据边界

Q 的范围、色条刻度、投影变量、梯度计算、箭头采样、expert 状态与安全定义需由原文确认。

## RSS2026_102
<!-- rss2026-meta {"visible_figure_label":"Fig. 3","figure_track":"data/table","domain_tags":["Q-Function","Bounded Hill","3D Surface","Temporal Small Multiples"]} -->

### 1. 截图身份

- 原文件：屏幕截图 2026-08-02 021153.png。
- 定位信息：`Fig. 3: Q-Function as Bounded Hill.`。
- 图的范式类别：四时刻 3D bounded surface small multiples；默认 3D 表现反例。
- **用户个人学习重点**：学习这种 3D 表示，但实际不够好看，明显不如之前的 3D 图。
- **补充核读**：红色 `Q=0` 参考平面和四时刻曲面拓扑有语义价值；默认 3D 网格、重复色条、小字体和大白边让第三维没有形成高级空间证据。

### 2. 图本身表达什么

Step 0/10/20/30 的 Q surface 从初始形态逐步形成 bounded hill，红色平面提供零值边界参照。

### 3. 逐元素与连接核读

**逐元素账本：**

- 四个 3D pane 使用紫—绿—黄连续曲面，顶部平台/峰值为黄色。
- 半透明红色水平面表示 `Q=0`；灰色三轴网格提供坐标参照。
- 每格重复一根竖色条和 Step 标题。

**箭头/连线账本：**

- 无时间箭头；面板标题中的 step 承担顺序。
- 曲面没有离散点标记，不能判断是观测、插值还是解析函数。

**关系账本：**

- 四格若要定量比较，必须固定 view、三轴范围、z 轴和颜色规范化；截图是否完全固定需查代码。

### 4. 全局构图与阅读路径

2×2 网格规整，但每格色条重复、pane 留白大，数据曲面实际占比偏小。视线在四个默认 3D 坐标框之间跳转。

### 5. 局部视觉语法

默认 viridis-like 色面、灰 pane、细轴和红参考面。透明平面可解释零水平，但与曲面交线没有被单独强调。

### 6. 为什么不够好

相机、box aspect 和照明没有强化峰谷；重复色条浪费空间，小字号和默认网格削弱成稿感。若只关心安全域扩张，2D contour 会更直接。

### 7. 可以吸收的绘图知识

- 3D temporal surfaces 适用于曲面拓扑或零平面穿越本身是结论。
- 固定所有视角/尺度，改用共享色条，并突出 `Q=0` 交线而不是铺大红面。
- 同时提供一幅 2D contour/安全域面积曲线以核验定量变化。

### 8. 不足、误读风险与不应照搬

不照搬四个默认 mplot3d pane、重复色条和大白边。透视面积、峰高和颜色亮度不能替代数值比较；无采样点时不要暗示实测地形。

### 9. 本图最值得学习什么（收录理由）

保留“时间演化曲面＋零参考面”的证据意图，同时明确何时应降维为共享 contour。

### 10. 证据边界

曲面来源、插值方式、相机参数、共享 norm、Q=0 平面透明度、step 含义和实际坐标单位未确认。

## RSS2026_103
<!-- rss2026-meta {"visible_figure_label":"Fig. 2","figure_track":"method/schematic","domain_tags":["LDA","Multi-Modal Diffusion Transformer","Action Expert","Visual Expert","M9"]} -->

### 1. 截图身份

- 原文件：屏幕截图 2026-08-02 021413.png。
- 定位信息：`Fig. 2: Architecture of LDA.`。
- 图的范式类别：条件输入—多任务卫星—共享扩散主干—蓝紫双专家细节栏的非对称架构主图。
- **用户个人学习重点**：重点学习蓝色主色调搭配紫色、高级配色、不规则而平衡的排版、无无用留白、浅色背景、圆角、适当阴影和恰当子示意图。
- **补充核读**：归为 M9/T1 的高优先级“蓝紫双专家”变体，不另建母版。高级感来自角色—颜色—尺度一致：蓝色 action expert、紫色 visual expert、浅蓝共享主干、左侧输入/任务卫星和右侧细节栏共同围绕中央锚点。

### 2. 图本身表达什么

LDA 接收 observation、language、diffusion timestep 与 task selection，经 VLM/token、时间编码和 task embedding 条件化，在 Multi-Modal Diffusion Transformer 中联合去噪 action chunks 与 DINO future；右侧 MM-DiT block 展开 action/visual 双专家如何通过共享 self-attention 交互。

### 3. 逐元素与连接核读

**逐元素账本：**

- 左上大圆角 Conditioning Input 容器包含 Obs、Language、VLM、VLM Tokens、Sinusoidal Encoder、`f_t` 和 Task Embeddings。
- 左下四张不等宽任务卡分别表示 Forward Dynamics、Inverse Dynamics、Policy、Visual Planning，每卡用简图＋一条短公式说明训练目标。
- 中央最大浅蓝圆角模块 `Multi-Modal Diffusion Transformer` 是视觉锚点；上方 action chunk 与 DINO future 是两类输出。
- 下方蓝色 action/noise 分支与紫色 visual/current DINO 分支各经 Linear Projection 和 register/token 序列进入主干。
- 右侧大圆角 MM-DiT Block 细节栏：蓝/紫两路 AdaLN、Cross Attention、LayerNorm、FFN 围绕共享 Multi-Modal Self-Attention；Task & Time Embedding 与 VLM Tokens 位于共享条件位置。

**箭头/连线账本：**

- 左侧条件 → 中央主干｜深蓝直箭头｜conditioning data flow。
- 下方蓝/紫输入 → Linear Projection → register/token → 主干｜两色分支箭头｜专家身份。
- 主干 → action chunk/DINO future｜向上箭头｜联合输出。
- 中央 → 右侧细节栏｜黑色虚线括边/引线｜结构展开，不是数据流。
- 右侧蓝/紫残差回路和加号节点｜同色细箭头｜专家内部计算；共享 attention 处才发生两色语义汇合。

**关系账本：**

- 颜色不是装饰：蓝固定 action expert，紫固定 visual expert，近白/浅紫任务卡固定条件和任务上下文。
- 大小不是装饰：中央主干最大、右侧机制细节次之、输入容器与四任务卡作为异构卫星；层级与论文贡献相符。

### 4. 全局构图与阅读路径

阅读路径先从左上输入到中央主干，再向上看双输出；需要机制时沿虚线展开到右侧 MM-DiT block，训练目标则回看左下四张任务卡。左上大容器、左下不等宽卡、中部大锚与右侧高细节栏形成非对称平衡，未强行等分。

### 5. 局部视觉语法

- 取证显示色：近白容器 `#F9F8F7`、主浅蓝 `#D9E2F2`、模块蓝 `#9CC2E5`、深蓝 `#2F5395`、浅紫 `#ECEEF7`、深紫 `#702F9F`；共享 attention 内可见蓝紫过渡 `#AABFE3`。
- 阴影低对比、统一向外右下；圆角半径按容器尺度变化但语言一致。
- 标题/模块名使用字腔饱满的圆润无衬线/等宽感短标签，数学式保持正式斜体；不能仅凭 PNG 确认源字体。

### 6. 为什么有效

每个大区都同时有文字名称和可见对象：输入有 token/编码器，任务有简图和公式，主干有双类输出，细节栏有双专家路径。颜色、形状、尺度、位置和箭头共同编码同一职责，因此内容密集却不杂乱；负空间主要是箭头与标签通道。

### 7. 可以吸收的绘图知识

- 作为 M9/T1-B：中央共享主干＋蓝/紫双专家＋异构任务卫星＋右侧机制展开。
- 浅色大容器承担背景，深色只用于边、字、箭头和少量 register 标记；蓝紫只在共享计算处渐变。
- 不规则美必须由主脊梁、尺度层级和可追踪对齐线支撑；四张任务卡不必等宽，但顶部/底部基线与内边距一致。
- 每个阶段保留一个操作性视觉落点，框内文字以简称和必要公式为主。

### 8. 不足、误读风险与不应照搬

双专家配色只适用于确有两套语义分支的系统；普通单支路方法不应硬套蓝紫。右侧细节较密，终稿需核验小字和 token 数量；阴影不可加重成 UI 发光。中央主干与右栏的展开关系必须标清，不能被误读为串行第二模块。

### 9. 本图最值得学习什么（收录理由）

它把蓝紫角色配色、异构模块尺度、非对称平衡、轻阴影和可理解子示意统一到同一架构语义中，是本轮最值得重点吸收的流程图。

### 10. 证据边界

精确字体、源矢量色、阴影参数、register/token 数量是否按比例、各任务公式完整性、训练/推理路径与 right-block 重复次数需回到论文/源图确认。
