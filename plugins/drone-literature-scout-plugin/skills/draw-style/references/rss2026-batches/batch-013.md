### 1. 截图身份

- 原文件：屏幕截图 2026-08-02 010618.png。
- 定位信息：`Fig. 7. Comparison of Learned Policies from PegInsert.`；左侧是六项结构指标雷达图，右侧是 DINO/GMM 学到的 PMM 与 cluster 视觉样本。
- 图的范式类别：多指标雷达图＋有限状态结构图＋聚类样本缩略图的混合证据图。
- **用户个人学习重点**：雷达图的指标表示、字体和配色都值得学习；前三张属于不错的例子，应归类并强化通用要求。

### 2. 图本身表达什么

图比较 ENAP(GMM)、ENAP*(DINO) 与 ENAP(Oracle) 在 PegInsert 上的六项结构指标 APF、SRN、SR、ASD、CSS、LVR。右侧进一步展示 DINO 与 GMM 变体学到的状态、转移和自环，并将若干状态连接到视觉 cluster；读者不仅知道哪条雷达轮廓更大，还能检查模型复杂度与状态语义。

### 3. 逐元素与连接核读

**左侧雷达图：**

- 六条辐射轴等角分布，轴名贴近外圆；部分指标标有上箭头，提示优化方向，但不同指标是否统一归一化仍需正文确认。
- 三种方法用砖桃、橄榄绿、柔金黄区分，轮廓内为低透明填充；重叠区不完全遮蔽后层。
- 每个顶点附近直接写数值，数值颜色跟随方法；标签错位避让，减少依赖图例来回查找。
- 外圈黑线比内部灰辐射线更重；没有高密度同心刻度文本，图面保持轻。

**右侧 PMM：**

- DINO 为三状态 `q0/q1/q2`，GMM 为四状态 `q0–q3`；圆节点、自环与有向边均用同一蓝灰墨色。
- 转移标签 `c0/c1/c2` 紧贴所属箭头；双向边和自环通过曲线分离，避免把两个方向压在一条直线上。
- 两个 PMM 各自置于浅近白、淡蓝虚线圆角容器；右边 cluster 样本另置灰虚线小容器，结构与实例不混为一个框。
- cluster 图片用 `c0/c1/c2` 黑底短标签与 PMM 边标签对应，建立跨表示身份。

### 4. 全局构图与阅读路径

左侧约四成宽负责综合比较，右侧约六成宽负责结构解释；中间深灰竖虚线是证据类型分界。读者先扫雷达轮廓，再沿同一方法名进入右侧状态结构，最后看 cluster 图确认状态含义。图例横跨底部，让三种雷达颜色不占用中心数据区。

### 5. 局部视觉语法

- 原生实色代表值：GMM 砖桃 `#C87B60`、DINO 橄榄绿 `#839F39`、Oracle 柔金黄 `#F0D98C`；蓝灰结构墨色的高频显示像素约 `#4B6772`。
- 雷达色只承担方法身份；PMM 改用单一蓝灰，cluster 用真实图像。三层证据不重复争夺同一组颜色。
- 字体与 Comic Sans MS/Comic Neue 类圆润手写体强相似；截图无字体元数据，不能断言作者源字体。
- 数值使用同色、较粗、略倾斜字形，轴名更大；正式复现时应先保证终稿尺寸下可读，再追求手写感。

### 6. 为什么有效

雷达图单独使用容易只剩“面积大小”印象；本图把轮廓背后的状态数、自环和转移结构直接画在右侧，使指标解释落地。颜色只负责方法，结构用中性墨色，视觉照片只负责实例，编码职责清楚。直接数值降低雷达图精确读值困难，粗大文字使缩小后仍明显。

### 7. 可以吸收的绘图知识

- 将本图归入 M6“分布与多指标诊断”，但允许一个 M2 辅助面板承接同一方法的结构实例。
- 雷达图绘制前统一所有指标“越高越好/越低越好”方向并公开归一化；不得只因多边形面积更大就宣称综合更优。
- Python 可用 Matplotlib 官方 radar projection 示例改写：每条方法线叠 `fill(alpha≈0.15–0.25)`，顶点用小 marker，数值用 `annotate` 分角度偏移；PMM 另用 NetworkX/Graphviz 或矢量软件绘制。
- 图例、直接数值和线型至少保留两种方法身份通道；灰度打印时不能只靠砖桃/橄榄/金黄。

### 8. 不足、误读风险与不应照搬

雷达轴量纲与归一化口径不在图内；三种半透明填充叠加后形成第四色，可能误当新类别；直接数值较多，若方法再增加会拥挤。右侧 PMM 状态布局并非按概率或距离定量，不能把节点间几何距离当数据。Comic Sans 类字形在严肃论文中应克制使用，不适合长说明。

### 9. 本图最值得学习什么（收录理由）

重点学习“雷达量化＋状态结构＋视觉实例”的三层闭环，以及砖桃/橄榄/柔金三色、半透明填充、大号手写圆体和顶点直接数值；不把它拆成孤立的雷达图配色碎片。

### 10. 证据边界

### 2. 图本身表达什么

横轴为 similarity threshold，另一轴为 RNN loss configuration（`w/o L_pred`、`All`、`w/o L_contrast`），高度和颜色共同编码 performance。两个任务的实测点经插值形成表面，以显示阈值和损失配置的联合影响。

### 3. 逐元素与连接核读

- 两个 3D 面板使用相近相机角度和透视；标题置顶，竖虚线分隔面板。
- x 轴保留 0.4、0.6、0.8 等阈值；类别轴用三个文本档位；z 轴写 Performance 并给数值刻度。

- 后方三维 pane 为超浅灰，细灰网格用于定位；真实点和主轴明显更黑。
- 每幅图配独立竖色条，只标本面板最低/最高值；因此两图相同颜色不必然代表完全相同 performance。

### 4. 全局构图与阅读路径

两幅图并列、视角一致，读者先看表面高低趋势，再检查黑点位置，最后用色条确认范围。表面占据面板主体，标题、轴名和色条都使用大号圆润字体，避免三维透视把文字压小。

### 5. 局部视觉语法

- 原生色条代表锚点：低值蓝 `#568BBF`、中段近白 `#F9F8F6`、高值酒红 `#B94E5E`；两幅面板端点有轻微抗锯齿/采样差异。
- 黑点核心接近纯黑，边缘有抗锯齿；浅灰 pane 约 `#F2F2F2`；曲面网格为白色。
- 红白蓝不是类别三色，而是一条连续显示色图；不能截取中间色当独立方法色。
- 轴标题与面板标题与 Comic Sans MS/Comic Neue 类手写圆体强相似；数学下标仍应由公式字体承担。

### 6. 为什么有效

它把“哪里真正测过”和“点之间如何估计”明确分层：黑点提供可核查的采样位置，插值面提供整体趋势，白网格提供曲面拓扑。大字号、有限刻度和浅背景使三维图没有陷入常见的细线小字问题。

### 7. 可以吸收的绘图知识

- **Python**：类别轴编码为 0/1/2，`meshgrid` 生成规则网格；插值只输出 `Z_fit`。`plot_surface(..., cmap=custom_cmap, edgecolor='white', linewidth≈0.8–1.2, antialiased=True)` 后用 `scatter(..., c='black', s≈50–70, depthshade=False)` 叠实测点。
- 色图用 `LinearSegmentedColormap.from_list(['#568BBF','#F9F8F6','#B94E5E'])`；根据正式基准决定是否以 `TwoSlopeNorm` 锚定中点，不能默认把均值当零点。
- **MATLAB**：`surf` 配 `EdgeColor='w'` 和自定义 colormap，随后 `scatter3(...,'k','filled')`；散点若不规则，使用 `scatteredInterpolant`/`griddata` 前必须声明插值与外推策略。
- 固定 view、axis limits、box aspect、类别顺序、光照和字号；surface 与 scatter 使用同一 x/y/z 坐标，不靠目测抬点。

### 8. 不足、误读风险与不应照搬

类别轴只有三档，连续表面会让读者误以为类别之间存在连续中间状态；独立色条削弱跨任务绝对比较；曲面在实测点之外的外推边界不明。红白蓝通常暗示相对中点的正负差，如果这里只是低到高性能，应在 caption 明确。3D 透视不适合要求精确查值的主结果，必要时配二维热图或表格。

### 9. 本图最值得学习什么（收录理由）

重点收录“黑色实测点＋红白蓝插值曲面＋白色曲面网格＋大号坐标文字”的完整合同，而不是只记红蓝渐变好看；同时保留 Python 与 MATLAB 的等效复现骨架。

### 10. 证据边界

插值算法、是否外推、每个黑点的重复次数/不确定性、两个面板是否共享规范化、作者实际软件和字体文件均未从截图确认。上述代码是视觉与语义等效方案，不冒充原始源码。

### 1. 截图身份

- 原文件：屏幕截图 2026-08-02 010803.png。
- 定位信息：`Fig. 2: The DISC architecture.`。

- **用户个人学习重点**：整体流程感高级，重点学习左侧任务句字体、适当阴影；类似图可由系统生成，再由用户手工重新描述。
- **补充核读**：截图不能确认 Visio。图的关键不在软件，而在“任务规范只决定执行哪个策略、观测只进入最终策略”的清楚分流。

### 2. 图本身表达什么

语言指令经 T5 Encoder 得到任务 embedding `e_l`；Weight Initialization Network 产生初始参数 `θ(0)`，中央 learned iterative refinement 通过 Forward、Backward、Meta 及 `z/∇z/Δθ(t)` 更新成 `θ(t+1)`；最终参数配置 Policy Network，观测由 Obs. Encoder 编码后进入策略并输出动作 `a_t`。

### 3. 逐元素与连接核读

- 左下是一张轻微不齐的纸张卡，完整写出 `“Pick up the alphabet soup and put it in the tray.”`；黑箭头向上接 T5 Encoder。
- T5 卡输出橙色 embedding `e_l`，一支进入初始化网络，另一支沿中央容器上边直达迭代模块，表示任务条件贯穿两阶段。
- 初始化网络以浅黄圆角框表示，输出 `θ(0)` 的三条叠片，再经黑色折线送入中央主容器。
- 中央淡蓝大圆角容器是视觉锚；Forward、Backward、Meta 三张灰蓝卡纵向排列，橙/蓝箭头形成前向、梯度和元更新关系。
- 右侧绿色立体小块标 `z`、`∇z`、`Δθ(t)`，再汇入加法节点并更新深蓝参数片 `θ(t+1)`。
- 最右 Obs. Encoder 由地球图标输入，黑箭头向下接 Policy Network；策略从更新参数和观测两路接收信息，输出机器人动作。

### 4. 全局构图与阅读路径

阅读顺序先左后右，但中央容器占最大面积。左侧“语言→参数初始化”较窄，中央“迭代”最宽，右侧“部署策略”再次收窄，形成窄—宽—窄节奏。任务卡、初始化卡、中央容器和策略卡的大小不同，但主链清楚，不是随机错位。

### 5. 局部视觉语法

- 任务卡字体与 Comic Sans MS/Comic Neue 类强相似；引号、自然换行和不规则纸边共同强调“原始人类任务”。
- 卡片使用外部右下接触阴影＋柔和扩散阴影；中央容器阴影更弱，避免所有框机械悬浮。
- 浅蓝承担编码/系统域，浅黄承担初始化，浅绿承担中间量，橙/蓝承担不同更新路径；本轮不升格其精确色号。
- 数学变量使用 serif/math italic，节点名使用无衬线或圆体，语义层次清楚。

### 6. 为什么有效

自然语言没有被压成普通小框，而以任务指令卡成为明确起点；参数生成与观测执行被分成两路，中央迭代过程又通过空间和颜色集中。适当阴影只强调卡片层级，不替代连接语义。

### 7. 可以吸收的绘图知识

- 将“任务指令卡”加入 M3：纸张对象只用于自然语言、演示或人类约束输入，内容必须完整可读。

- 阴影统一为两层外部右下阴影；纸卡可略强，普通算子框减弱，主容器不做发光。

### 8. 不足、误读风险与不应照搬

中央橙/蓝箭头较多，局部平行线容易混；`×T` 与循环终止关系不够直观；地球图标可能被误解为真实世界而非 observation source。阴影和圆角若原样套在所有技术图上会显得卡片化。不能从截图断言使用 Visio或确定字体。

### 9. 本图最值得学习什么（收录理由）

学习“完整任务指令卡＋参数生成主容器＋部署策略”的层级，以及只在关键卡片使用柔和阴影和圆润短字体；它属于清晰 M3 架构，不因好看就升格为 RSS060 那类 M9 模板。

### 7. 可以吸收的绘图知识

- 训练—部署图应明确“何时冻结、谁继续更新、动作写回哪里”；冻结用状态标注或虚线边界，不只靠浅色。
- 长反馈沿外框走线并在终点处明确箭头，避免一条穿过所有模块的对角线。
- 若模块类型相近，维持普通三段式 M3；只有出现异构对象、双向协同和多个尺度时再升级 M9。

### 8. 不足、误读风险与不应照搬

颜色没有稳定角色，照片与矢量图分辨率/边界不一致；细节模块较小，缩小后可能难读；冻结虚线跨距较长，若无文字会不清楚。不能把“清晰但普通”误升格为个人配色模板。

### 2. 图本身表达什么

Dataset 面板给出奖励集中在右上区域的二维离线数据；`α=100、10、1.0、0.1` 依次展示 learned policy density。较大 α 更保守、更贴近宽数据支持；较小 α 逐渐分裂、收缩并可能集中到数据支持之外，揭示 regularization 的偏差—越界权衡。

### 3. 逐元素与连接核读

- 五幅正方形面板横向等距，坐标域、长宽比和视角一致；只有标题/α 改变。
- Dataset 使用暖色多层闭合 contour，内部标出 `r=0.0/r=1.0` 语义区域。
- 后四图用蓝色密度层：`α=100` 支撑较宽，`α=10` 出现多个不规则模式，`α=1.0` 只剩少数窄模式，`α=0.1` 缩成右上小岛。
- 同一面板内部颜色由浅到深表示相对密度，闭环间距反映局部密度变化快慢；没有可见粒子时不能推断样本量。
- 图例依靠面板顺序和标题，不额外重复色条；若各面板独立归一化，会影响跨图强度比较，需正文确认。

### 4. 全局构图与阅读路径

从左到右是数据基准→正则化由强到弱的有序序列。相同的正方形框和共享二维位置让读者只比较支撑形状，而不是被坐标或相机变化干扰。留白均匀，标题短，适合一行呈现。

### 5. 局部视觉语法

- contour 使用多个离散 levels 近似连续密度，边界柔和但不做光晕。
- 颜色只编码面板内密度，`α` 由标题文本编码；本轮不提取精确色号。
- “宽支撑→分裂→收缩”的结论由面积、连通分量数量和位置共同表达，不只由颜色深浅表达。

### 6. 为什么有效

正则化参数最重要的后果不是单个 scalar 指标，而是策略在二维动作/状态域覆盖哪里。共享域的密度序列直接展示 support collapse、mode splitting 和 out-of-support 行为，比四条均值曲线更形象。

### 7. 可以吸收的绘图知识

- 归入 M7 的“有序密度支持序列”，适用于动作分布、策略占据、能量盆地、可达集或概率质量随超参数变化。
- Python 可用 `contourf(X,Y,density,levels=shared_levels,cmap=...)`；MATLAB 用 `contourf`。若密度来自 KDE，固定带宽、网格、边界处理、归一化和 levels；否则形状变化可能只是绘图参数变化。
- 面板标题按真实参数顺序排列；对数跨度可显示为 `10^2→10^-1` 或明确 `α` 值，不用渐变色再重复编码参数。
- 需要精确比较总质量/面积时，另配支持面积、KL、OOD rate 等量化图；contour 负责形状，不代替统计检验。

### 8. 不足、误读风险与不应照搬

截图缺完整色条、轴名和单位；若每图独立归一化，深色不能跨图比较绝对密度；KDE 带宽可人为制造“波纹”和小岛。不能称 contour 为真实轨迹，也不能从轮廓层数推断样本数。

### 9. 本图最值得学习什么（收录理由）

学习共享二维域中的“有序密度支持变化”：同一算法只改变 α，让支撑从宽到碎裂再到收缩；把用户描述的波纹准确归类为 filled contour/KDE，而不是新增模糊图表类型。
