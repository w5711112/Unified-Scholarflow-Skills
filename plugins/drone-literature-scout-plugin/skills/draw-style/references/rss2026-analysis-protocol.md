## 2. 证据边界

- 只依据截图内可见图形、文字、caption、坐标、图例和统计说明读图；图内看不到的信息写“未从截图确认”。
- Caption 明确写出的定义优先于视觉猜测；只在可见 `Fig. x` 时写入 `visible_figure_label`。
- 用户提供的论文标题、图题或 caption 片段只用于匹配截图时，**标题只作定位**，单列为“定位信息”；不得混入“用户个人学习重点”，也不得把标题措辞提炼为绘图规律。
- 允许结合用户给出的领域范围判断“可能的领域线索”，但不得用外部论文上下文填补截图空缺。
- 本任务不需要为每张图反查论文。图题或 caption 足够时就停在截图证据边界。
- “图表达了什么”与“绘图技巧值得学习什么”必须分开写，不能用风格评价代替语义阅读。
- 必须先用原始分辨率看完整图；字符、上下标或连接端点仍不清楚时再看局部放大。逐字符核对后仍无法确认的内容写“未从截图确认”，不得凭领域习惯补字。

## 3. 每张图的完整分析卡

每张卡必须包含以下栏目，不能只写简短审美印象：

1. **截图身份**：逻辑 ID、原文件名、可见图号、图轨、领域线索；另起一行写**图的范式类别**：`论文总图（系统/方法/网络架构）`、`知识点/局部原理示意图`、`论文数据图（统计/表格/空间数据可视化）`或确有必要的混合类型。可注明“疑似 MATLAB/Python/矢量软件制作”，但必须标成视觉推断。
2. **图本身表达什么**：先给一句精确视觉主张，再沿阅读顺序说明对象、输入、过程、比较、输出、结论和边界。必须指出 caption 明示了什么、图形本身又证明/展示了什么。
3. **逐元素与连接核读**：按下面三本账逐项记录，不能只写概括句。
   - **逐元素账本**：每个子图、容器、模块、照片、图标、数据标记、坐标轴、刻度、单位、公式、图例、标题、caption 和有语义的阴影/底色。不得用“等”“若干”省略具有独立含义的对象；大量同类散点可以报告编码、数量是否可数、密度、范围和分布，而不逐点抄录。
   - **箭头/连线账本**：使用 `起点 → 终点｜线型/颜色｜边标签｜可确认语义`。逐一核对箭头方向、汇合、分叉、反馈和跨面板连接；没有箭头头部的线只能称“连接”，不能擅自解释方向。
   - **关系账本**：分别写清**图—图关系**（共享条件、对应、对比、唯一变化因素）和**文字—图形关系**（文字锚定哪个对象/边，caption 为哪个视觉事实提供正式定义）。
4. **全局构图与阅读路径**：画布比例、主次区域、面板划分、进入点、阅读方向、视觉中心、空白、密度、对齐和跨区连接。
5. **局部视觉语法**：对象形状、2D/2.5D/3D/视角、字体层级、公式、数值、颜色、线宽、虚实线、箭头、图例、标记、底色、边框、间距和标签锚点。
6. **为什么有效**：把“效果好”落实到认知作用，例如减少来回查图例、保持可比条件、显式呈现不确定性或让空间关系可见。
7. **可以吸收的绘图知识**：写出可迁移规则、适用场景和不适用条件；区分“确认已有规则”“强化”“新增”“细化”“与现规则冲突但并列保留”。
8. **不足、误读风险与不应照搬**：指出裁切、字体、遮挡、比例、统计口径、颜色依赖或上下文缺失等问题；优秀图也要写边界。允许明确评价“结构值得学、外观一般”或反之，不把所有入选图写成同一等级。
9. **本图最值得学习什么（收录理由）**：单独写一段，指出用户为什么可能选中它、本图相对于其他图的独特贡献，以及应优先吸收的 1–3 个技巧；不能只是重复“为什么有效”。
10. **证据边界**：逐项列出未从截图确认的信息，避免把视觉推测当论文事实。

每张卡另设“**用户个人学习重点**”与“**补充核读**”：前者记录用户为什么选中该图，后者只补足未被点出的元素、关系、技巧和风险。二者不得混写。

每张卡标题后紧跟机器可读元数据：

```markdown
<!-- rss2026-meta {"visible_figure_label":"Fig. 5","domain_tags":["Manipulation","RL"],"figure_track":"data/table"} -->
```

`figure_track` 只允许 `method/schematic`、`data/table`、`mixed`。

## 4. 方法/示意图的追加核验

- 列出全部关键对象及其空间/拓扑关系，说明谁是输入、状态、模块、环境、约束和结果。
- 核对因果、数据流、反馈、状态更新、循环与终止；无定义箭头不得解释成因果。
- 多面板必须说明共享条件与唯一变化因素；同色、同形、同符号是否跨面板保持一致。
- 说明 2D、2.5D、3D 或照片叠加为何必要；透视是否承载体积、高度、遮挡或空间穿越，而非装饰。
- 图内文字和 caption 的职责要分开：哪些语义通过对象直接表达，哪些只能由 caption 补充。

## 5. 数据图/表格的追加核验

- 图形类型、横纵轴、单位、方向、线性/对数尺度、排序、基线、平均区与具体条件分区。
- 每个方法的点估计、精度、样本量与统计单位；无法读出准确数值时只给视觉近似并明确标注。
- 误差棒/阴影究竟是标准差、标准误还是 95% CI；caption 未定义时不得猜。
- 是否有显著性标记、截断轴、双轴、归一化或视觉夸大风险。
- 图例顺序是否对应柱/线顺序；颜色在灰度打印和色盲条件下是否仍可区分。
- Caption 是否自包含地说明任务、方法、统计口径和主要结论。

## 6. 批次综合

五张逐图卡后必须写本批综合：

- 本批出现了哪些视觉家族，不能错误收敛为单一浅色框图。
- 共同有效原则与相互冲突但适用条件不同的原则。
- 方法/示意和数据/表格分别新增了什么技巧。
- 哪些只适用于 PPT、Obsidian、正式论文方法图或正式论文数据图。
- 对 `draw-style` 的候选影响；用户确认前只写在批次卡，不直接覆盖稳定参考文件。

## 7. 冻结门槛

只有用户明确确认当前批分析准确后，才运行 `freeze-batch`。冻结要求本批每个逻辑 ID 都有标题和合法元数据；任何一项缺失时整批保持 `pending`。冻结后重跑 `check`，确认源文件大小和 SHA-256 未变化。
