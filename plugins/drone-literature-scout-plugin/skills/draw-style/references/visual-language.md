# 跨场景科研视觉语言

## 1. 图首先是视觉解释，不是正文搬家

- 让几何、轨迹、栅格、设备、状态、模块和数据标记等**视觉对象承担主要解释**；直接标注优先于大图例、通栏说明框和外置公式卡。
- 图片必须有**强视觉解释能力**：移除标题、图注和正文后，读者仍能沿图中对象复述当前视觉主张。
- 公式、数字和状态贴近所解释的格子、节点、边、模块或几何对象内部或近旁；不得把一堆正文公式排进框里冒充直观解释。
- 图内总标题可省略或弱化；caption 解释“结论和边界”，图内标注解释“对象是什么、如何变化”。
- 图内与紧邻图例是一个解释单元：图内优先表现对象、动作和空间/时间关系，图例补充术语、箭头语义、数字来源与不可推断边界。二者不能同时把同一必要解释留空。

## 2. 对象、关系和阅读顺序

- 主因果链与主轨迹较粗；辅助关系较细或虚线。箭头只表达有定义的流向、因果、更新或映射，并由图内动词或紧邻图例说明具体语义，不用无意义装饰箭头。
- 使用对齐、浅底色、留白和细分隔线组织分区；同级面板保持相同内边距、间距、标题基线、线宽、尺度和信息密度。
- 对比图共享输入、尺度、边权、初始状态和终止条件，只改变被比较因素；视觉上显式写出共享条件。
- 复杂主题优先一个主场景加一个必要局部放大图；局部图必须回答主图中看不清的具体问题，不重复主图。
- 连接线短；**连线不得穿过标签、公式或数字**。跨区长连接应沿空白通道或边缘布线。

### 2.1 立体层次与阴影

- 方法卡片、模块或容器需要从背景中明确抬起时，使用统一的**两层外部右下阴影**。第一层是贴近边缘、偏移小、模糊小的**接触阴影**，第二层是偏移稍大、模糊更宽、透明度更低的**扩散阴影**。
- 两层阴影沿同一右下方向，深度从视觉锚点向普通模块递减。阴影不得侵入文字安全区，不得跨过箭头，不得变成发光、重黑边或不受控的漂浮效果。
- 定量数据图保持读数优先。只有固定偏移背板或不改变数据端点的轻投影可使用这种深度语法，误差棒、点位、区间和真实柱顶永远位于阴影之上。

选择合同：

1. 先写唯一视觉主张和读者任务。若对象异构、存在双向反馈或两套协同子系统，首先判断 M9；**M9 是全库最高优先级之一的模板级参考**，适用时优先于普通等尺寸系统框图。
2. M9 不适用时，再按读者任务选择其他母版；简单状态变化、普通统计比较和真实三维事实不因 M9 重要而被强行改造成流程图。
3. 每张图只选择**一个主母版**；只有一个必要的次级问题无法由主母版回答时，才增加**最多一个辅助母版**。
4. 颜色、箭头、标记、阴影和字体属于叠加语法，不单独决定母版；不得把多个参考图的装饰元素无条件拼贴。
5. 两个非 M9 母版都能回答时，选择维度更低、面板更少、证据更直接的方案。
6. 不直接模仿某一张 RSS 图的全部外观；逐图分析卡只用于核对证据、适用条件与反例。

## 4. 科研浅色体系不是固定模板

默认可从**论文教材风**与科研浅色体系开始：浅蓝表示输入/观测，浅绿表示安全/可行，浅红表示风险/障碍，浅橙表示反馈/警告，浅紫表示策略/备选，浅灰表示上下文。颜色的实际含义必须在当前图中固定，不能机械套色。

- 使用浅色填充和较深边界；关键对象可用较饱和色突出，但深色面积不宜压过主体。
- 系统架构图可使用**近邻浅色**：浅紫、浅蓝、米白、浅绿之间以克制色差和明度层级区分区域，不用互相冲撞的高饱和主色。左侧仅命名层级、右侧承载对象和流程时，采用**左窄标签区、右宽流程区**，不要让标题栏与主图各占一半。
- 需要卡片层次时使用**统一轻阴影**：同一方向、相近模糊半径和低不透明度覆盖全部同类卡片；阴影只把对象从底色上轻微抬起，不制造悬浮 UI 或强烈立体发光。
- 同一颜色只承担一种核心语义，并辅以形状、线型或短标签，兼顾色盲和灰度打印。
- 允许局部透明渐变表达距离、概率、风险或影响范围；禁止无语义发光、强阴影和装饰渐变。
- 不统一成浅色圆角框图：空间几何、照片标注、轨迹、统计图和系统流程各用最合适的视觉家族。
- 多路输入的语义类型不同时，让**异构分支使用不同视觉介质**：时序可用错位平面，局部几何可用 bin/采样点，状态目标可用路径或紧凑符号；再以统一容器、线宽和汇合点收束，不能把所有分支压成同一种框。

### 4.1 用户确认的稳定个人配色：六个核心色族

普通新图只从下表选 **2–4 个核心色族**。主色承担对象身份或强调，浅色只承担背板、区间、上下文和透明度层级，不增加新类别。

| 核心色族 | 主色 | 固定浅色 | 默认角色 |
|---|---|---|---|
| 紫 | `#8062AA` | `#E4DEEC`、`#F1EEF5` | 策略、方法主轴、关键边界；**少量深紫＋大面积浅紫** |
| 蓝 | `#4D94D8` | `#D7E0EF`、`#CFE5FE` | 输入、观测、参考场、目标 |
| 绿 | `#839F39` | `#E6F3E5`、`#D8F1CF` | 安全、可行、结构或动作 |
| 橙 | `#FD7F0E` | `#FDF1E6`、`#FECB9E` | 轨迹、反馈、警告或待处理量 |
| 红 | `#F14C4A` | `#FBE1E0`、`#FFF5F4` | 风险、障碍、负结果或关键误差 |
| 灰 | `#5F5F5F` | `#D8D8D8`、`#EDEDED`、`#F2F2F2` | 坐标、辅助结构、上下文、禁用态与最浅中性承载面 |

`#FBD35A` 是小面积金黄附件，只用于关键点、星标或少量数值强调，不是第七个核心色族。

灰色内部按明度分工：`#D8D8D8` 可承担可见节点或较实的分区，`#EDEDED` 用于 halo、辅助面和弱背景，`#F2F2F2` 用作算法卡正文、3D pane 或近白容器。三者是同一灰色家族的层级，不应同时被解释成三个数据类别。

| 色阶 | 精确停靠点 | 使用条件 |
|---|---|---|
| **蓝色顺序色阶** | `#CFE5FE → #9CCBFE → #63B1FE → #0096FE` | 非负连续量、有序阶段或可行度从低到高 |

### 4.4 唯一选择顺序

1. 先问数据是否是连续数值；是则从四条连续数据色阶中选一条。
2. 若主母版是 M9，检查 T2；若是同构抽象问题—方案对比，检查 T3；若是正式策略方法图，检查 T1。
3. 三套模板都不匹配时，从六个核心色族中选 2–4 个，再用浅色扩展层级。
4. **只有精确复现才查询历史档案** `color-font-archive.md`；不从档案为普通新图拼接调色板。

截图色号是最终显示像素，不能唯一反推作者源色和 alpha。显示色阶和抗锯齿近邻色不能扩展成新类别；完整取证边界见历史档案。


## 5. 字体、公式、数字和标签

| 字体角色 | 首选 | 回退 | 使用边界 |
|---|---|---|---|
| 数据图坐标、刻度、数字 | **DejaVu Sans Regular/Semibold** | Office/WPS 用 **Arial** | 终稿一般 10–11 pt；核对饱满的 `0`、`6/8/9`、负号、单位括号 |
| 正式方法图英文 | **Source Sans 3** | **Arial** | 模块名、简短说明与面板字段；Regular/Semibold 分层，不用过细字重 |
| 中文 | **Source Han Sans SC / Noto Sans CJK SC** | Windows/WPS 用 **Microsoft YaHei** | 与英文字重、x-height 视觉重量和终稿尺寸协调 |
| 数学公式 | **STIX Two Math** | **Latin Modern Math / Computer Modern** | 变量斜体，函数、单位和说明正体，向量记法一致 |
| 少量手写短标签 | **Comic Sans MS** | **Comic Neue** | **手写感只用于短标签**：单条任务指令、少量节点名或演示卡；禁止用于坐标、密集刻度、公式和 caption |

- 先按角色选字体，再按载体选回退；同一图一般只保留一个正文无衬线家族、一个数学家族和可选的手写短标签家族。
- 逐字符核对所有文字、公式、数字、单位、编号和上下标。伪文字、重复序号、断裂路径、错误公式或无法解释的箭头直接判失败。
- 图内只放不可替代的短公式和关键数值；推导留在正文。数值必须能由可见对象或明确数据核算。
- 标签放在被说明对象附近，**标签保留安全距离**；同类标签使用一致锚点。
- PNG 只能提供字形相似证据，不能确认作者原字体；RSS2026_060–070 的详细匹配候选保存在 `color-font-archive.md`。

## 6. 逻辑闭环与术语落地

语义完整与解释准确是前置硬门槛。解释型图与紧邻图例合起来必须形成：

`对象是什么 → 输入从哪里来 → 箭头/变换做什么 → 输出怎样得到 → 结论的边界是什么`

数据图使用对应链条：`变量是什么 → 数据从哪里来 → 视觉编码是什么 → 可读结论是什么 → 统计边界是什么`。

### 6.1 解释责任方

- 每个非显然术语、缩写、符号、数字、箭头、线型和颜色身份必须指定一个主要**解释责任方**：图内直接标注，或紧邻图例解释。
- 图内优先让机制可见，并使用贴近对象的短动词，例如“计算”“筛选”“离散更新”“入队”“淘汰最旧项”“均匀取样”。
- 图例补充名称展开、箭头具体含义、数字/样本/阈值来源、跨面板身份和方法边界；不能只复述面板标题。
- 正文可以展开推导和背景，但不能充当远距离补丁。读者只看图与紧邻图例，也应能完成主张的最短复述。

### 6.2 闭环验收

1. 做**孤儿元素审计**：枚举实际出现的文本、符号、数字、箭头、线型、颜色身份和样本编号，逐项核对解释责任方。
2. 做**读者复述测试**：不借助原论文正文，读者能回答“对象是什么、箭头做什么、结果从哪里来、图不能证明什么”。
3. 若数值或样本数量承担结论，必须说明其来自原文、数据、公式计算还是示意选择；概念性数量不得伪装成论文事实。
4. **简洁是保留逻辑闭环后的最小表达**。删除后若出现名称悬空、箭头无动作、数字无来源、输入输出断链或边界消失，即为结构性失败。

不能通过删除必要语义换取清晰。信息装不下时增大画布、重排，或在同一图像文件内使用多面板；不要把必要说明缩成不可读小字。

## 7. 生成、失败与修正边界

- 先写可核验的语义蓝图，再写最终提示词；蓝图顺序固定为知识点与单一视觉主张、布局骨架与阅读顺序、对象清单及位置关系、过程编码、精确夹具、语义配色、字体、间距与原生输出要求、明确禁项。
- 精确夹具固定对象总数、唯一标识、顺序、坐标/锚点、路径停止位置、跨面板共享条件和禁止自由补值。
- 结构性失败必须重写语义蓝图与提示词并整图重生成；单一局部小错误才进入最小局部修正。
- Image2 只保留一个主候选，不为比较而生成多个变体。提示词预检后一次成图；纯审美轻微偏差不触发重做，禁止对已语义合格候选做大面积覆盖。

## 8. 多图效率与验收

- 每个知识点一个独立 Image2 请求，按当前可用安全并发槽同批发出，不把无关知识点塞进同一画布。
- 合格图立即冻结；只把失败图在改过蓝图或提示词后送入下一波并发。
- 不做为比较候选而设的独立联系表；按目标使用宽度一次完成八项检查。
- 公开质量档位时选择最高档；保存最高原生分辨率的原始 PNG，不重新压缩、不插值放大。Obsidian 场景按**实际 Obsidian 宽度**验收。
