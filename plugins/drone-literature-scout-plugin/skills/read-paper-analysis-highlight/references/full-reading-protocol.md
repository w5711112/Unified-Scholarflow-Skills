# 全文精读协议 V4

## Pass 0：身份与不可变边界

- 原样记录 Obsidian 标题、来源行、下载链接、DOI、Zotero key、等级、状态与 block ID
- 核验 Zotero 父条目、PDF 附件、`application/pdf`、页数、正式版本和 SHA-256
- 替换旧 AI 批注时必须从无批注 backup 开始
- support link、摘要页和项目页只能作补充证据，不能替代 PDF
- 开始重做时状态保持或恢复为“待精读”

## Pass 1：按视觉顺序建立论文地图

从 PDF 第 1 页读到最后一页。双栏排版、跨栏图、脚注、图注、页眉页脚和参考文献不能只依赖抽取顺序。

新建的全文台账根对象必须写 `schema_version: 4`；历史 schema v3 只做兼容读取，不能作为新任务模板。

每页记录：

```text
page
sections
text_read: true
equations_checked: checked|not_present
figures_checked: checked|not_present
tables_checked: checked|not_present
captions_checked: checked|not_present
figure_audits: []
key_questions: []
candidate_evidence: []
selected_annotations: []
rejected_fragments: []
unresolved: []
```

一页可以没有批注，也可以有很多条；没有配额。`unresolved` 必须为空。`figures_checked: checked` 时 `figure_audits` 至少有一项；`figures_checked: not_present` 时必须是空列表。

第一遍回答：

- 论文类型是什么？
- 问题、任务、输入、输出、setting 与成功标准是什么？
- 与哪些工作相关，依赖、组合、挑战或扩展了什么？
- 现有方案的具体失败是什么？
- 最本质 motivation 是什么？
- 作者声明哪些贡献？每项贡献由哪里支撑？

完成论文地图后立即做研究问题审计：

- **Interesting（问题值得研究吗）**：矛盾是否真实、非平凡、仍有缺口
- **Solvable（问题可解吗）**：在什么假设下可解；论文解决到哪里；哪里仍不可解
- **Current level（当前研究水平）**：理论、算法、系统、工程或部署处于哪一阶段
- **Impactful（问题影响大吗）**：影响对象、后果与证据强度
- **新旧问题/方法分类**：新问题新方法、新问题老方法、老问题新方法，或老问题成熟方法的新组合

五个字段采用**唯一语义归属**，不能把同一判断换词后写五遍：

- **Interesting 只回答**矛盾为什么真实、非平凡和值得研究，不在此重复论文方案或实验结果
- **Solvable 只回答**在什么假设下能解到哪一步、哪些部分仍无解，不在此重复问题重要性
- **Current level 只回答**该方向处于理论、算法、系统、工程或部署的哪一阶段，并用已有部件与本文增量定位
- **Impactful 只回答**影响谁、会造成什么性能或安全后果，以及现有证据有多强；具体实验数字留在实验栏首次完整陈述，必要时只作短指代
- **新旧问题/方法分类**只给创新类型与判据，不再复述完整方法链

`一眼记住`、What、Why、How、理论、实验、局限、Pros/Cons 和拓展也遵守同一原则：同一结论只在最合适的位置完整写一次，其他位置不得用同义改写再次陈述，只能补充新的机制、条件、证据、边界或应用判断。去重是信息归并，不是删减；原文事实、条件、样本、数字、局限与复现缺口必须保留。

后续所有方法与实验阅读都要能回填 **What / Why / How**、**Pros / Cons** 和“**如何拓展与利用**”；不能在结尾凭印象补写。

## Pass 2：方法、理论、实现与设计因果

逐句读取方法段、公式、算法框、架构图和图注，建立：

| 项目 | 必须记录 |
|---|---|
| 问题 | 失败现象、困难来源、成功条件 |
| 输入/观测 | 传感器、变量、历史、特权信息、尺寸、预处理 |
| 表示 | 状态、图像、点云、图、走廊、隐变量、轨迹或安全集合 |
| 学习/目标 | 算法、损失、奖励、约束、优化器、课程、随机化 |
| 输出/动作 | 物理意义、单位、范围、频率、下层接口、后处理 |
| 安全/理论 | 定义、公式、定理、模型、可行性和成立假设 |
| 运行链路 | 感知、推理、过滤/优化、控制器、硬件、时延、回退 |
| 复现 | 代码、数据、版本、参数、随机种子、训练算力、耗时与缺失项 |

### 主链模块的八项解释合同

控制、感知和机器人论文中，凡模块影响“环境怎样被看到、状态怎样进入算法、动作怎样产生、怎样保证安全、命令怎样执行”，都要在 `CLAIM_EVIDENCE_MAP` 中保存下列八项：

1. **模块任务**：这个模块解决哪一个具体问题，属于感知、状态估计、决策、规划、安全修正还是执行
2. **输入来源**：输入是传感器直接测量、地图查询、状态估计结果、上游网络输出，还是训练阶段才有的仿真真值
3. **输入内容**：关键字段分别代表什么对象；论文报告时保留单位、维度、坐标系、时间范围和频率
4. **实际处理顺序**：按运行先后展开内部步骤；“编码、选择、投影、融合、约束”等动词必须说明对什么量做什么判断或变换
5. **输出的物理意义**：输出属于谁、表示什么，例如机器人希望执行的速度、障碍物的估计速度、地图中的查询距离或最终控制命令
6. **下游接口**：输出交给哪个模块，是否还会被裁剪、筛选、优化、安全修正或低层控制器转换
7. **训练阶段与部署阶段**：哪些输入、奖励、标签、仿真器或探索只在训练使用，真实运行时实际保留哪些模块
8. **条件与失效边界**：方法成立所需的传感器、地图、预测、动力学、时延、可行性或分布条件；失败时会发生什么

八项中的未知必须写“论文未报告”，不能用常识补齐。解释顺序优先沿一次真实运行的数据流；不能用术语替代解释，也不能把两个普通名词拼成复合词后默认初学者已经理解。实验语境中的 `baseline` 首次出现写成“用于比较的基准方法（baseline）”，并说明比较的输入、输出和控制变量。

每个设计选择都回答：

1. 它针对什么失败？
2. 机制为何可能解决这个失败？
3. 替代方案是什么？
4. 引入什么依赖、假设或新失败模式？

每个公式都解释：

- 一句话大白话：它在当前方法链里解决什么麻烦
- 每个变量、下标、上标、常数、算子和函数；有单位、坐标系、取值域与正负方向时一并说明
- 从左到右怎样计算，以及关键量变大、变小、变正或变负分别意味着什么
- 等式/不等式左右两侧、优化目标与约束方向的含义
- 在系统数据流中的位置，以及它属于训练期奖励/损失还是部署期动作约束
- 邻近文字明确给出的设计原因、数值稳定性和权衡
- 成立假设是否在实验中满足，哪些失效方式没有覆盖
- 原始 PDF 页码和公式编号

公式含三个以上需要解释的符号或解释超过两条列表时，在 Obsidian 使用嵌套折叠“概念解释”。禁止只标公式编号、理论名称、一个大矩形，或用“鼓励安全/提高性能”替代变量与计算逻辑。

## Pass 3：实验、图表与怀疑

每个主要主张建立：

```text
Claim: 精确主张
Evidence: PDF 页 + 章节/公式/图/表 + 观察到的关系
Condition: 环境、平台、baseline、样本、速度、算力与指标
Status: supported|partially_supported|not_established
Boundary: 没有覆盖的范围
```

### 表

逐项读表题、行列标题、单位、实验条件、baseline/消融变量、关键单元格和正文解释。整表矩形不能代替分析；选最小但足以重建比较关系的区域。

### 图

每一幅 `Fig.` 及其每个子图都必须实际视觉检查，不能只读 OCR、正文转述或图注。逐图建立 `figure_audits`：

- `figure_id`、`pdf_page`、`caption_read`，以及正文中全部引用这幅图的位置
- 每个 panel 的角色和 panel 之间比较关系
- 颜色、线型、形状、符号等视觉编码；坐标轴、单位、范围、刻度与图例
- 模块、箭头、数据流、输入、输出和控制/训练/部署方向
- 数值、趋势、成功例、失败例、异常点和可见边界
- `observed_claims`：图本身能支撑什么，不能支撑什么
- `text_formula_table_consistency`：与正文、公式、表格是否一致或存在张力
- `limitations_or_anomalies`：缺失的硬件、频率、条件、误差条或不充分比较
- `annotation_regions`：真正值得框选的最小有效区域
- `unresolved`：读不清或无法对账的问题；非空时不得完成

可选视觉组成如果确实不存在，写字面量 `not_present`；不得用空列表冒充检查完成，也不得在未检查时写 `not_present`。`observed_claims` 和 `text_formula_table_consistency` 必须是非空列表。只有无法用文本 quads 表达关系时才用 area；必须写 `visual_object`、主张和框选原因。

### 证据语言

- **论文报告**：作者测量、证明或直接观察
- **可以推断**：证据允许的最强谨慎解释
- **尚不能证明**：证据没有覆盖的更强结论
- **论文明确承认的局限**：作者主动写出的限制或失败
- **未报告与疑点**：关键平台、参数、硬件、训练、统计或回退机制没有给出

每项实验结论必须先写“对象—条件—样本—结果—边界”。正面结果、样本限制、作者明确承认的局限和分析发现的复现缺口是四类不同证据：

- 原文报告全部 N 次成功/无碰撞时，先准确写在什么条件下 N/N 成功，再说明 N 较小或条件较窄
- 未报告硬件/求解器只能降低复现性，不能改写已报告成功率、失败率或零碰撞结果
- 跨页续句和失败原因必须确认指向同一组仿真/实机试验，不得因版面断页错配对象

写入笔记前逐项复述这五个字段；无法从 PDF 定位的字段写“未报告”，不靠常识补齐。

内部证据台账继续保留 PDF 文件页码，例如 `（PDF第 4 页）（公式 8）`，用于追溯、批注定位和回读；不使用期刊印刷页码。写入完成态 `已AI全文读` Callout 时去掉 `（PDF第 N 页）`，只显示原文明确存在的结构锚点，例如 `（公式 8）`、`（图 3）`、`（表 II）` 或 `（算法 1）`。没有结构锚点的主张仍在内部证据中保留页码，但成品正文不补写页码标签。

## Pass 4：指定作者外部证据

从作者行、脚注或贡献声明识别全部一作、共同一作和通讯作者。只调查这些作者，除非用户扩大范围。

先做身份消歧，再调查：

- 本科、硕士、博士与毕业院校
- 当前机构、实验室、职称、导师身份
- 研究方向、项目、代表成果与本文关系
- 荣誉、奖项、人才项目、学术头衔
- IEEE/ACM Fellow、Senior Member、Member
- Google Scholar Citations、H-index、来源与统计日期
- 当前机构 QS 排名、榜单版本与官方来源
- 是否可谨慎判断为领域重要学者

所有外部事实保存 URL 与 `as_of`。对 URL 做实际可达性检查；403、429、Access denied、CAPTCHA 或登录墙不能作为用户唯一入口。缺失字段写 `not_publicly_verified`，不能写 0。

Obsidian 建立嵌套折叠“作者与团队背景”；PDF 在作者姓名上做紫色 `author-name` 批注，第一行写 `外部信息：`，明确它不是论文正文证据。

## Pass 5：全库知识归属

写论文笔记前扫描整个 Obsidian 仓库：

- 已有规范解释：扩充原位置
- 使用 `[[笔记#标题|别名]]` 或 `[[笔记#^block-id|别名]]` 跳到精确位置
- 没有合适归属：交给 `obsidian-note-style` 检查当前项目的知识文件预算；预算冻结时只扩充现有主笔记或请求用户授权，不自行新建知识文件
- 论文 Callout 只保留理解本文所需的短解释
- 长公式直觉、通俗类比和百科解释放在知识笔记与嵌套折叠 Callout
- 重命名或移动后重新验证全部链接可达

## Pass 6：选择证据原子

证据原子可以是：

- 完整问题/因果/机制/设计理由/结论句
- 方法名、baseline 或参考文献角色
- 关键数值、训练规模、速度、场景数、样本数、频率、硬件和时延
- 论文明确的 support link
- 公式、图、表或算法框的最小有效视觉区域
- 作者承认的局限和分析发现的证据缺口

选择没有数量配额。拒绝 `we propose`、`success rate remains` 等无对象、无条件的脚手架；但不能把示例误当成封闭黑名单。方法名和数字只要批注补足角色、指标、条件和意义，就可以成为合法证据原子。

## Pass 7：评论、坐标与语义复核

- 普通评论第一行 `结论：`
- 作者评论第一行 `外部信息：`
- 至少再写一行机制、意义、复现、边界、疑点、定位或来源
- 不设置字符上限；禁止纯翻译和空泛判断
- 文本高亮以 `quote → quads → actual_text` 校验
- 区域同时保存 `pymupdf-page-top-left` 的 `rect` 与 `pdf-page-bottom-left` 的 `zotero_rect`
- 每个区域渲染确认实际对象、范围与评论一致

## Pass 8：笔记、Zotero 与完成状态对账

- 每条 Obsidian 主张映射到台账/manifest 证据
- 每条 PDF 批注映射到一个笔记问题和精确 claim
- 重复证据只在回答不同问题时保留
- support links 单列 GitHub、视频、补充材料、项目页、数据集；未提供要明写
- Zotero 批注必须原生、可编辑、可删除、无锁
- 只删除 manifest 中可追踪的旧 AI 批注，保留用户手工批注
- 清理可再生的中间文件
- 全部门槛通过后才把状态改为“已AI全文读”

## 后续参考文献

只保留需要复现或质疑核心方法、承担 baseline、理论来源或关键数据来源的高价值文献，并写清“为什么追”；不做无理由书目堆砌。
