# 知识归属、前置链与全 Vault 链接合同

## 真实 Vault 根与唯一知识归属

当前工作目录、论文项目或 Git 工作区不自动等于 Vault。任何全库检索、新建、链接校验或知识索引前，从当前路径逐级向上找最近的 `.obsidian`，其父目录才是唯一 Vault 根；找不到就停止写入。

- 用 `scripts/build_obsidian_knowledge_index.py --vault <当前路径或子路径> --output <索引文件>` 建索引，并以 `find_notes_by_basename()` 全库查询文件名，同时检查 aliases、标题与块链接
- 排除 `.obsidian`、缓存、测试 fixture、运行目录与可再生中间文件，但不能排除当前研究项目的正式 Markdown
- 任何创建、移动、合并、删除、标题改名与块 ID 修改前生成 `KNOWLEDGE_PLACEMENT`：候选主笔记、文件预算/冻结规则、全库匹配、独有内容与写入决定

匹配规则不可简化：

- **0 个匹配**：先检查知识文件预算、冻结清单或用户指定承载文件；存在时写入允许的现有主笔记，不能因 0 个同名文件自动新建
- **1 个匹配**：它是唯一主笔记，直接纠错或扩充；即使在 Vault 根也禁止另建同名副本
- **多个匹配**：停止新增；比较全部版本，将独有且可靠的内容合并到逻辑主笔记，修正显式路径链接并验证标题/块可达，之后才可删除冗余副本

禁止因为只扫描当前项目便断言知识点不存在。删除副本前核验绝对路径；用户手工内容未合并时不得删除。已有合适笔记时禁止为了一个术语新建 Markdown；只有无知识文件预算、现有主笔记确实无法承载且用户明确同意时，才可新建。

### 当前无人机论文项目的知识文件冻结

论文精读知识枢纽**冻结为两个现有文件**，任何论文精读流程不得新增第三个：

- `安全控制与<YOUR_METHOD>.md`：安全控制、CBF/HOCBF、safety shield、<YOUR_METHOD>及其控制接口
- `路径规划与环境表示.md`：路径/<YOUR_TASK>、地图、距离场、走廊、点云与感知表征在规划中的作用

**作者履历不进入知识枢纽**：作者与团队背景随对应论文保存，不能为作者、实验室或团队另建主笔记。`深度强化学习.md`、`PX4飞控.md`、`Sim2real与实机部署.md` 等通用主笔记继续承担原职责，不算新增枢纽。新概念优先写入最合适的现有文件并增加稳定标题或块 ID；无法归属时停止并请用户决定。

## 主位置、引用位置与前置链

- 主位置保存完整定义、机制、例子、边界与相关概念；引用位置只写当前任务为何需要它、一句最小解释与精确链接
- 发现主位置错误就修正主位置，不能在别处另写“正确版本”与旧内容并存
- Obsidian 单向 WikiLink 已自动形成反向链接；确有必要时在主位置增加“在当前研究中的使用”回链
- 新概念按 **基础概念 → 扩展概念 → 论文特定用法** 排列；标题层级表达继承、组成与用途，不能机械并列

硬前置例：Dijkstra 代价场先有 Dijkstra 最短路并区分松弛迭代与奖励；ESDF 位于距离场、SDF 下游；HOCBF 位于安全集合、基础 CBF、相对阶下游，HOCBF-QP 再作为部署实现。基础已存在则扩充唯一主位置；基础缺失仍受文件预算约束。

前置链回答“依赖什么”，跨课程桥回答“另一个已学结构能否帮助回忆”，二者不能混同。概念桥只按专门参考的人工确认门执行。

## WikiLink 与块 ID

链接优先级固定为：

1. `[[笔记名#标题|简短别名]]`：独立标题的默认形式
2. `[[笔记名#^块ID|简短别名]]`：只定位一句定义、公式或操作
3. `[[笔记名|简短别名]]`：确实需要打开整篇时使用

显示文字服务当前句子，目标负责精确定位；不写“点击这里”。同一段同一概念只保留一个清晰入口。Markdown 表格内必须把别名分隔符转义为 `[[笔记名#标题\|简短别名]]`，逐行复核列数并扫描未转义的 `[[...|...]]`；目标、标题和别名两侧不能随意加空格。

块 ID 使用稳定、可读的英文短语，随段落移动且全 Vault 唯一；已有合适标题时不滥用。供 `obsidian://open?...Note%23%5EBlock` 指向折叠 Callout 的论文锚点，唯一 `^block-id` 必须位于论文标题下方、Callout 之前的独立行；真实点击并确认标题进入可视区，不能把 ID 放到来源行末。

禁止无别名长链接、只跳几千行文件顶部、给每次重复术语加链接、链接到不存在标题/易变序号/重复块 ID。

## `LINK_GRAPH`：全库出链、入链与语义缺链

任何新增、移动、删除、标题或块 ID 改名都只生成一份 `LINK_GRAPH`，包含修改前基线、全部入链/出链、改名影响面、语义缺链候选和修改后结果。固定流程：

1. 从当前路径定位 `.obsidian`，运行 `scripts/check_obsidian_links.py --vault <当前路径> --json` 保存修改前问题集合
2. 对目标文件、标题与块 ID 查全部入链，并检查目标笔记全部出链
3. 只修复语义明确项；每轮复扫并对比问题数量、来源、目标与类型没有新增
4. 最终全 Vault 的 `missing-file`、`missing-heading`、`missing-block`、`ambiguous-file`、`relocatable-file` 五类全部为 0

修复边界：

- 文件移动只有同名目标唯一时才自动改真实相对路径并保留锚点/别名
- 失效标题链接到现有等价标题；标题过大时在真实定义处补稳定块 ID，不能降级到文件顶部
- 失效块在真正承载知识的位置补全库唯一块 ID，再更新全部引用；不得在来源处伪造目标
- 文件缺失先全库找改名后的规范主笔记；知识确实缺少时扩充最合适的现有主笔记
- 资源确实不存在时保留有信息量文字并注明缺失；**不得创建空白占位笔记**、空白图或虚构标题只为归零

链接检查器只能发现失效链接，不能发现已有概念**仍以纯文本出现**的语义缺链。每次新增/扩充正文提取新增技术名词、算法、理论、软件、接口和上游概念；索引命中**已有唯一知识位置**时，在第一次承担解释或推理作用处建立精确链接。同一段一个入口即可，不把每个重复术语染蓝。

## 写入、恢复与故障预防

- 默认无界面解析 UTF-8 Markdown，不启动 Obsidian、浏览器或 Computer Use。保持原 LF/CRLF 与 BOM，批量写入前备份并核验绝对路径
- 临时备份默认放在 **Vault 外**；只能放 Vault 内时置于检查器明确排除的隐藏目录并先验证不在扫描范围，最终通过后删除
- 检查器返回非零通常表示发现问题，必须解析 JSON `issues`；无法解析、脚本异常或文件不可读才是运行故障
- PowerShell 双引号会解释 Markdown 反引号，可能把 `` `r `` 变成回车。含反引号、LaTeX `$` 或中文时使用 UTF-8 unified diff、单引号 here-string 或参数化脚本，写回后核验 BOM、LF/CRLF 与全文件 diff
- `apply_patch` 因 split writable roots 失败时生成范围限定 diff，先 `git apply --check` 再应用；不得用 GNU `patch.exe` 反复试错
- 依赖缺失先从 import、requirements 或锁版本确认，再以当前解释器安装并重新 import；不能让可恢复的 PyYAML 等缺失阻断治理
- 中断恢复先检查 `.orig`、`.rej`、`NUL`、补丁、隐藏备份和修改时间；依据当前文件与全 Vault 复扫恢复，不重放已成功修复，也不在状态不明时覆盖
