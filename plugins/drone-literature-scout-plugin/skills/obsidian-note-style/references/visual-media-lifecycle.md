# Obsidian 知识点视觉与媒体生命周期合同

## `VISUAL_DECISION`：本地 0–1 门与论文级一次审计

**每个本轮新增或扩充的正式知识点**写入时立即独立判断为 `0` 或 `1` 张，不等待论文收尾：

- 算法、控制、空间表示、曲线、轨迹、网络、状态转移和机制比较等能显著降低理解成本的知识点，没有合格现图时默认 `1`
- 只有已有合格等价图、视觉化无理解增益、证据不足会引入猜测、或全部路线均过不了质量门时才为 `0`；理由只写任务结果
- 多个知识点逐标题决定；不能用一张总览图替代各自判断，也不能以公式 Callout 豁免
- 判为 `1` 后，图像可解析、嵌入有效、图后折叠图例完整、第二层公式 Callout 保留，才可完成

知识点是可独立成标题的算法、表示、方法、数学/控制主题、模型、机制或结构；Dijkstra、PPO、ESDF、3D Ray Cast、SFC、B-spline、SDCQ、控制原理、轨迹生成和网络结构均独立判断。参考文献、总结、延伸阅读等组织性标题不属于知识点。**每个知识点独立判断为 `0` 或 `1` 张**；多面板仍是一份图像文件，**不限制整篇笔记或一次论文处理的总图数**。可视化知识点在没有合格现图时默认配 `1` 张。

`read-paper-analysis-highlight` 完成一篇论文正文、知识链接和笔记写入后，本 Skill**每篇论文只触发一次**全 Vault 视觉覆盖审计，覆盖 Vault 全部正式知识点，不限当前论文/改动笔记；不在论文阅读、逐段写入或单张图完成时重复触发，也不轮询。

## 轻量两层审计

1. **一次结构扫描**：论文收尾只运行一次 `python -X utf8 scripts/audit_obsidian_visual_coverage.py --vault <Vault路径> --json`；已有合格图快速跳过
2. **只深入无图候选或明确不合格旧图**：保留知识点、必需内容、证据边界、绘图路线、禁止内容五项；组织性标题直接判 0

不建评分系统、长期队列、守护进程或额外审计文件。轻量化只减少重复扫描/中间状态，不减少内容、分辨率、数学排版、视觉复核或替换安全。

## 调用 `draw-style`

缺图或旧图不合格时，将知识点语义、原文证据与输出约束交给 `draw-style`，场景固定为 `Obsidian 知识点图`。`draw-style` 独占语义蓝图、Image2 提示、维度选择与**八项硬质量门槛**；本 Skill 不复制绘图路线，只负责 Obsidian 生命周期：

- 提供知识点标题、图必须独立解释的内容、页码/公式/图号证据、计划嵌入宽度、保存目录
- 接收一个主候选，在**实际 Obsidian 宽度下一次完成八项检查**；不做独立联系表复核，不因放大可读就通过
- 合格后写正式引用；全部引用写入后只运行一次媒体审计

## 保存、嵌入与折叠图例

知识点按“第一层直觉 → 图 → 图例 → 第二层公式/形式化”排列。总标题只写标准名称；第一层统一为 `第一层｜直觉理解 | 一句话本质` 并直接说明机制。概念桥只有用户主动确认或此前逐条批准才进入。第一层继续解释输入—过程—输出；第二层写完整的必要计算链、逐符号人话、例子、性质来源、误解和边界，**公式解释可以比直觉层更长**。

同一结论只保留一处，解释闭环后不重复，但不能删公式疑问答案。内容多时用紧凑列表，不在每个短句之间插空行；只在正式公式、表格、等宽公式教学示意或语义阶段切换处换段；不稳定的 ASCII 改用紧凑表格或单行变化链。

网络图/用户截图放 Vault 根 `截图存放位置`；AI 生成/编程绘图放 `AI绘图存放位置`。使用根相对嵌入；每知识点只嵌入一个最终图。图后默认折叠：

```markdown
> [!info]- **读图与图例**
> - **怎么读**：阅读顺序与一句话机制
> - **名词**：术语、缩写和符号身份
> - **箭头/编码**：箭头、线型、颜色、编号的语义
> - **来源**：数字、样本、阈值或中间状态来源
> - **边界**：图不能推出什么
```

读图与图例不设固定条数；不适用项可省，但实际元素不能漏。核心原理、公式与成立边界仍在正文展开，图例不是第二份正文。

## 零质量衰减替换

旧图更新先生成独立候选；只有 `draw-style` 判定新图全部通过八项门槛，且本 Skill 确认关键维度均不弱于旧图，才替换。验证前保留旧图，禁止覆盖唯一资产。批量换图严格两阶段：先生成并验收全部新图，再更新正式引用；审计无缺失/歧义后最后删除旧格式。任何新图失败则保留整批旧引用。

## 媒体审计与孤儿清理

修改图片、Canvas、知识标题或嵌入后运行：

```powershell
python -X utf8 scripts/audit_obsidian_media.py --vault <当前路径> --json
```

- 从 `.obsidian` 定位真实 Vault，扫描全部正式 Markdown 与 Canvas，覆盖两个媒体白名单目录，报告 referenced、missing、ambiguous、unreferenced
- Markdown 用逐行围栏状态机，并识别列表内围栏；禁止跨全文正则配对
- 去除正常代码后的语义引用决定有效性；未去除代码的原始引用只保守保护同名媒体。闭合代码示例占位名记 `raw_missing`
- `parse_warnings`、正式 `missing` 或 `ambiguous` 存在时，`--apply` 必须拒删；原始扫描命中的现存媒体全部保护
- 默认 dry-run；未引用只是候选。同名/路径歧义保护全部候选，先改显式路径
- 删除必须同时使用 `--delete-unreferenced --apply`，逐项确认绝对路径位于两个白名单目录
- 删除前保存候选、反向引用、SHA-256，并确认 Vault 外备份/同步副本/版本历史可恢复；无恢复源停止
- 删除后立即重跑媒体与链接审计；不得删手工图、目录外资源、Canvas 资源或来源未核验图片
- 误判时停止清理，按精确名恢复、确认可解析，并用真实文件 SHA-256 比较；同步数据库对象哈希只能定位，不能冒充完整性校验

## Windows 写入与视觉复核

- 多步 PowerShell 前设 `$ErrorActionPreference = 'Stop'`；退出码 0 不能掩盖 `Copy-Item` 非终止错误
- Windows PowerShell 5 的 `New-Item` 不支持 `New-Item -LiteralPath`；对白名单精确目录用 `[System.IO.Directory]::CreateDirectory($path)`
- 部署用 `Copy-Item -LiteralPath`，逐个核对源/目标，只有源文件与目标文件的 SHA-256 相同才成功
- 中文 Skill/Markdown 用 `python -X utf8 <quick_validate.py> <skill目录>`；`UnicodeDecodeError` 指向 Windows 默认 GBK 时固定 UTF-8 重跑，不能改写成 ANSI
- unified diff 保留至少三行上下文；只有确需零上下文才用 `--unidiff-zero`，且先 `git apply --check`
- 受限测试统一用 `tests/test_support.py` 的 `writable_test_directory()`，写插件 `运行数据/test-temp` 并清理，不把 `TemporaryDirectory()` 放 AppData 或源码目录
- MathText 先在夹具完整渲染；SVG 先检 XML、`viewBox`、关键标签与外部资源，再渲染 PNG；XML 可解析不等于排版正确
- `view_image` 因 split writable roots 失败时不循环、不启 Computer Use；复制预览到批准目录并在可用时用 `node_repl` 的 `emitImage`，否则用无界面浏览器/确定性渲染器
- 同时检查原始分辨率与实际嵌入宽度：背景、裁切、公式/标签、箭头、图例、颜色、边缘留白、主体大小与正文一致性；仅文件存在/XML/放大可读不算通过
