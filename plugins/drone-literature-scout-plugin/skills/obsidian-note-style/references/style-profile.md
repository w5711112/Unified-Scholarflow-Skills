# 用户 Obsidian 研究叙述风格画像

## 语料范围

本画像来自整个 `C:/path/to/vault`：排除了 `.obsidian` 插件、回收站和 Excalidraw 图文件后，共 94 份 Markdown、约 114 万字。无人机 Kimi 笔记提供了文献综述的篇幅与信息密度参考；ROS、PX4、Sim2Real、强化学习等个人笔记提供了更稳定的组织与解释习惯。

## 稳定特征

- 采用多层标题，把“大结论—子问题—实现细节—风险/行动”逐层拆开。
- 用 **加粗** 标出结论、术语、约束和动作；少量 `==高亮==` 用于真正需要记住的决定。
- 高频使用表格，把概念、工具、论文、参数或路线并列比较。
- 在合适处使用 Obsidian 内链，把学习节点、系统组件和研究主题连起来。
- 不满足于一句抽象判断：会继续说明“做什么、为什么、怎么做、需要什么、有什么代价、下一步如何验证”。
- 偏好明确的条件句与边界：例如“前提是…”，“不要只…”，“必须区分…”。
- 面向初学者时沿真实数据流叙述：先说明数据由哪个传感器、地图、状态估计器或上游模块提供，再说明算法怎样处理，最后说明输出属于哪个对象、交给哪个下游模块执行。缩写和普通复合词都不能跳过这条链。

## 保留与排除

复制的是信息密度、分层和可执行性；不复制旧笔记中的未经核验数字、历史排名、重复段落、乱码或可能过时的事实。学术论断必须以本轮证据为准。
