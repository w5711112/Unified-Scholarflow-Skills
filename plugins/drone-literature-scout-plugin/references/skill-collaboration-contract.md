# 六领域 Skill 自动协作合同

## 插件级轻量故障协作

- 插件任务开始、Skill 新增/删除/改名或清单校验时，动态枚举 `skills/` 下全部含 `SKILL.md` 的目录；同一任务内拓扑未变时不重复枚举
- 只调用当前步骤需要的 Skill；每项业务语义只有一个负责人，其他 Skill 只交接输入、输出和验收证据
- 生成或修改简体中文 Obsidian 笔记或 Word/WPS 正文时，先由专业 Skill 负责事实与方法语义，再经过 `global.renhua` 的语言闸门，最后由 `obsidian-note-style` 或文档 Skill 处理格式。固定顺序为“专业语义草稿 → global.renhua → 格式 Skill”；格式步骤新增实质性正文时，新文字重新经过 `global.renhua`
- `read-paper-analysis-highlight` 完成正文与知识链接后，每篇论文只触发一次 `obsidian-note-style` 全 Vault 视觉覆盖审计；`obsidian-note-style` 判断每个知识点是否需要 0–1 张图并负责保存、嵌入、折叠图例和媒体审计，通用绘图与视觉验收交给 `draw-style`
- **正常成功路径不写故障库**，也不包装每次工具调用
- 当前组件已知脆弱、准备复用历史方案或路线已失败时，才调用 `global.collect-bug-update-accelerate` 的只读 `preflight`
- 出现异常、非零退出、权限拒绝、结果缺失或验证失败时调用 `capture`；同签名、参数和路线不得原样重试
- 一个真实故障一次成功解决并通过效果验证后即成为临时候选，不以出现或复用次数设门槛；只有本轮新增成功解法、复用结果或回归状态变化时检查，候选非空才通过 `global.collect-bug-update-accelerate` 加载 `promotion_audit.py`

## 权威、广搜—收敛与最小满足架构

- 每个原始 `SKILL.md` 及其强制参考始终是对应专业流程的最高权威；本协作合同只分配职责和交接，不得替代、删改或重新解释专业要求。计划、摘要、检查表、测试和故障记录只作证据记录。
- 当任务包含**研究方法、研究方向或解决方案选择**时，由该专业语义的唯一负责人通常先建立 **4–10 个真正可行候选**。候选要覆盖有意义的简单、严谨、高效、复杂或邻近学科路线；少于 4 个时必须记录由研究问题、证据、资源或可验证性导致的原因，**不得凑数**。
- 在看到最终结果前固定适用性、范围、证据、资源、验证负担、风险和预期贡献等标准：先淘汰不合格项，收敛到 **3–5 个短名单**，再用定向证据、推导或小试深化，最终保留**真正独立的 2 个**供完整比较；二者须在核心假设、机制、研究路径或验证信息上存在实质差异，参数、实现或表述变体不得占两个席位。导入、排版、迁移、绘图或故障处理等不包含研究选择的任务，不虚构候选池。
- 鼓励有依据的**跨学科迁移**和少见视角，但必须说明概念映射、假设边界、证据或验证路线以及相对简单方案的增益；**新颖性服从适用性**，不能用时髦或罕见替代专业证据。
- `global.collect-bug-update-accelerate` 只拥有技术执行可靠性与事故路线复用权，**不得充当任何专业领域**的正确性、适用性、新颖性、研究价值、方向接纳或方法排名裁判；注册表、`verified`、`preferred_route`、预检和晋升结论均不得覆盖归属 Skill 的专业判断。
- 全部六个领域 Skill 采用**最小满足架构**：每项语义一个负责人、一个当前事实源，复用已有产物；不新增重复清单、状态表、台账、注册表、守护进程、监听器或逐工具包装。精简只能去除重复和非必要组件，**不得删除、弱化或绕过**任何原始专业分析、证据核验、人工确认或归属 Skill 验收门。

## 协作登记表

| Skill 名称 | 唯一职责 |
| --- | --- |
| `zotero-obsidian-paper-import` | 正式身份与 PDF 前置核验、唯一性导入、原生合并及 Zotero/Obsidian 引用一致性 |
| `read-paper-analysis-highlight` | 全文证据/作者/PDF 批注 |
| `obsidian-note-style` | 知识归属/视觉覆盖/Callout/WikiLink/媒体集成 |
| `draw-style` | 跨场景科研绘图/视觉验收 |
| `drone-literature-scout` | 文献脉络与外部来源 |
| `searching-at-scale` | 通用大规模网页发现/动态字段采集/跨来源核验与调研收敛 |

`global.renhua` 是插件外部的简体中文语言闸门，不接管上述六个领域 Skill 的专业事实、证据或格式职责。`obsidian-note-style` 在写入前要求其通过，并继续独占 Obsidian 的知识归属、链接、Callout 与媒体集成。

## 交接关系

- `zotero-obsidian-paper-import` 交付唯一父条目、已核验附件和同一份写后对账，`read-paper-analysis-highlight` 与 `obsidian-note-style` 直接消费。合并保留原 key 时验证后沿用链接，跨版本更换附件时重新核对页码和批注定位。输入或状态未变时不重复搜索来源或读取全库，历史快照不改写

- `drone-literature-scout` 可调用 `searching-at-scale` 扩展查询和候选来源；`searching-at-scale` 返回候选和证据包，不直接写论文事实库。
- `drone-literature-scout` 继续独占论文门槛、venue、算力/部署门槛、论文库审计、方向评分和最终接纳。
- 需要绘图时，业务 Skill 交接使用场景、单一视觉主张、必须内容、证据与输出约束；`draw-style` 返回经过语义与视觉验收的主候选，业务 Skill 继续负责最终事实结论与落盘集成。
- `obsidian-note-style` 不复制通用绘图细则；它在全 Vault 审计中发现缺图知识点后调用 `draw-style`，并保留 Obsidian 路径、嵌入宽度、折叠图例与媒体生命周期的唯一职责。
- 用户明确要求检查或瘦身时，由 `global.workspace-hygiene` 盘点、生成精确提案并按批准范围清理。`global.collect-bug-update-accelerate` 只在真实技术故障时提供记录与路线复用；笔记语义合并、WikiLink、最终媒体归属和 Zotero 数据判断仍交给各自领域负责人。

- 第三方 Skill 的定期发现与审核由 `global.skill-ecosystem-governor` 的候选池统筹，`searching-at-scale` 只负责搜索和来源证据。候选记录是用户要求保留的成果，临时抓取文件按原清理规则处置；外部候选未经用户审核不得替换专业规则，不建立新的领域 Skill 或第二份组件注册表。

## 自我改进边界

稳定经验按 `global.collect-bug-update-accelerate` 的唯一治理路由归到唯一 Skill。临时候选涉及外部工具、版本、参数、安装或环境要求时必须核对官方资料；官方资料不可访问或冲突时保留临时方案且不循环联网重试。本地确定性问题直接用回归测试核验；公开资料不能代替本地效果验证。永久改进优先落在脚本、配置、依赖、安装器、环境预检或回归测试，其次才更新唯一负责人 Skill。基础设施类低风险改进必须效果等价、有失败后通过的测试、唯一编辑锚点，并通过聚合总览审计确认职责说明没有过期；领域语义、论文结论、重点判断和知识内容不得由故障层自动修改，必须满足归属 Skill 的证据合同。

未来新增 Skill 必须同步登记职责、组件归属和动态测试，并更新聚合总览中受影响的职责段与来源标记；不得把新 Skill 全文复制到其他 Skill。
